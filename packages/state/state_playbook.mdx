### Usage & wiring

Add the package via a path dependency (`stacked_kit_state: path: ../state`) and import `package:stacked_kit_state/stacked_kit_state.dart`. There is no locator or `@StackedApp` registration step — `stacked_kit_state` is pure Dart with zero Flutter dependency, so a `KitStateNotifier` is constructed directly rather than resolved through `StackedLocator`. The minimal usage drives a notifier with `track` and observes `stream`:

```dart
final notifier = KitStateNotifier<Profile>();
await notifier.track(repository.loadProfile()); // loading → success/error
notifier.stream.listen((state) => /* rebuild */);
notifier.state;     // synchronous current value
```

### Architecture

The package is a single inward-facing vocabulary: a sealed `KitState<T>` (idle/pending/loading/success/error) with `when`/`map` combinators sits at the core, wrapped by `KitStateNotifier<T>`, which holds the current state and a broadcast `StreamController`. Two static collaborators govern behavior — `KitStateTransition` (a legal-transition matrix queried by an assertion inside `emit`) and `KitFailure` (the normalized error shape carried by `KitError`, where `KitFailure.from` absorbs any thrown object). Two ports are stubbed for later phases: `KitStatePersistence<T>` hydrates terminal state across launches (with `KitNoStatePersistence` as the no-op default), and `KitRetryPolicy` is a testable value object whose `track` integration is scheduled. Dependency direction points strictly inward to `dart:async` plus `meta` — no Flutter, no cross-kit imports.


### Gotchas

There is no platform setup — `stacked_kit_state` is pure Dart with no native channels, permissions, or manifest keys. The broadcast `stream` does not replay the current value on subscribe; read `state` synchronously to get it. `emit` no-ops when the next state compares equal (every case implements value equality), and a transition outside `KitStateTransition`'s matrix trips an assertion in debug only — it is still applied in release, so illegal sequences never crash production but will silently slip past in tests unless `guardTransitions` is left on. In tests, drain the broadcast queue with `await Future<void>.delayed(Duration.zero)` before asserting a recorded sequence, and always call `dispose()` to close the controller.


### Testing

`package:stacked_kit_state/testing.dart` provides:

- **`KitStateRecorder<T>`** — subscribes to a notifier and records the emitted
  sequence for `expect(recorder.states, [...])` (leans on value equality).
- **`KitScriptedStateNotifier<T>`** — bypasses the guard so tests can push
  illegal or repeated sequences via `script` / `scriptAll`.

```dart
final notifier = KitStateNotifier<int>();
final recorder = KitStateRecorder<int>(notifier);
await notifier.track(Future.value(42));
await Future<void>.delayed(Duration.zero); // drain the broadcast queue
expect(recorder.states, const [KitIdle<int>(), KitLoading<int>(), KitSuccess<int>(42)]);
```

### Decisions / ADRs

The package is deliberately standalone: its only backing dependency is `meta` (for `@immutable`/`@protected`), with everything else drawn from `dart:async`. It exists to be the *intended* common async-state vocabulary that the other kits' ports converge on — but that unification is a documented later phase, so there are no cross-kit imports today and each kit still ships its own typed results. Choosing pure Dart (zero Flutter) keeps the vocabulary usable inside services and ViewModels without a Flutter binding, and makes the `KitStateRecorder` / `KitScriptedStateNotifier` tests in `testing.dart` plain `package:test` suites. The transition guard is debug-asserted rather than runtime-enforced so release builds never crash on an unexpected sequence.
