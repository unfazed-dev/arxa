### Overview & role

Standalone port for legal/compliance surfaces — a versioned KitComplianceDocument registry, KitConsentStore-backed consent tracking with a typed KitConsentStatus, a pure KitConsentGate, and a KitLicensesService over Flutter's LicenseRegistry. Zero third-party runtime dependencies.

### Usage & wiring

Add `stacked_kit_compliance` as a path or git dependency — it is `publish_to: 'none'`, so it is not published to pub.dev. The kit mandates **no** Stacked locator or `@StackedApp` wiring (it depends on no other kit), so the only thing you register is the `KitConsentStore` port: bind `InMemoryKitConsentStore` for the working default, or your own durable implementation. Populate a `KitComplianceRegistry` with your `KitComplianceDocument`s, then drive the flow with `KitConsentService.statusFor` / `outstandingDocuments()` and `KitConsentGate.evaluate()`, which returns `allowed` or `blocked(outstanding)` in registry order. App version is passed in as a plain string — the kit takes no `package_info_plus` dependency.

### Architecture

This package intentionally depends on **no other kit** (not `stacked_kit`,
`stacked`, or `stacked_services`). Persistence is behind the `KitConsentStore`
port; the app binds `InMemoryKitConsentStore` or its own durable
implementation. Nothing here imports Flutter widgets.


### Gotchas

- **v0 (this package)** — standalone, own `KitConsentStore` port, in-memory
  default, exact-string versioning.
- **One document per kind** — `currentDocuments` and the gate collapse to a
  single current document per `KitComplianceDocumentKind` (latest registered
  wins). Two documents sharing a kind — most plausibly `custom` — gate as one;
  give each its own kind if both must be presented.
- **Deferred** — durable store bindings (secure storage / a backend), semver-aware
  version policies, locale-negotiation of which document to present, and any
  consent UI. Add as consuming apps need them. Unifying the typed results onto
  `stacked_kit_state` is a documented later phase; there are no cross-kit imports
  now.


### Testing

`package:stacked_kit_compliance/testing.dart` re-exports the API and adds
`FakeKitLicensesService`, a `KitLicensesService` backed by a scripted list of
`LicenseEntry`s (build them with `LicenseEntryWithLineBreaks`) so license
collection can be tested without a Flutter binding. The in-memory consent store
is used directly in tests.

### Decisions / ADRs

The kit is standalone by design — it depends on **no other kit** (not `stacked_kit`, `stacked`, or `stacked_services`) so the `KitConsentStore` port stays the sole coupling point and consuming apps own persistence. Its only backing is the Flutter SDK: consent value types and the license reader use `@immutable` and `LicenseRegistry` from `package:flutter/foundation.dart`, yielding **zero third-party runtime dependencies**. App version is passed in as a plain string rather than pulling `package_info_plus`, and version comparison is exact-string (no semver parsing) so `2026-07-01` and `1.2.0` are equally valid version schemes.
