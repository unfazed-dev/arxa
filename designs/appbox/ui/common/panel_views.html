{# The multi-view panel frame (the Activity Panel's chrome): ONE reusable frame for both sides. The activity panel (left) registers its own views per shell (runs / artifacts / commits / files / thread); the frame owns a head (active view label), a body the caller fills via call/caller, and a bottom views bar whose icon carousel switches views by hx-swapping the body. Macro-only, so importing it never emits stray markup. Usage: {% import "ui/common/panel_views.html" as pv %} {% call pv.frame(spec) %} …markup for the active view… {% endcall %} The panel owns and persists its own state: the
(with the user's drag-resized width) is never replaced — a view switch swaps the body in place and refreshes head + bar out-of-band, so the active icon and the label always track the server's panel state. htmx's global view transitions animate every swap. spec: side — 'left' | 'right' (drives the ids: #panel-…) label — the active view's label, shown in the head views — [{ id, icon, label, href, active }], one carousel button each; icon is a Lucide name for the icon() global, href hx-swaps that view's fragment into #panel--body size? — 's' | 'm' | 'l' (default 's'): the shell's persisted panel width (facade session state, panelSize[side]); used as the panel-size-* class fallback when panelSizePx is unset sizeHref? — present when the panel can be resized; renders the drag handle (panel-frame-handle) that drag.js wires to POST px width to /design/panel/size/:side (live width in .panel-frame-width) panelSizePx? — persisted px width; when set, applied as an inline width style on the aside instead of the panel-size-* fallback Part macros (head / body / bar) carry their own ids and an `oob` flag: a view-switch response renders the body content (targeted) plus head and bar with oob=true; a stage-driven re-feed renders body + head + bar all with oob=true. #} {% macro head(spec, oob) %}
