{# The multi-view rail (story map · Chat-Centric Layout → Rails): ONE reusable rail for both sides. Each shell registers its own views (runs / artifacts / commits / files / chat); the rail owns a head (active view label + collapse affordance), a body the caller fills via call/caller, and a bottom bar whose icon carousel switches views by hx-swapping the body. Sibling of rail.html; macro-only, so importing it never emits stray markup. Usage: {% import "ui/common/rail_views.html" as mv %} {% call mv.frame(spec) %} …markup for the active view… {% endcall %} The rail owns and persists its own state: the
(with the user's CSS-resize width) is never replaced — a view switch swaps the body in place and refreshes head + bar out-of-band, so the active icon and the label always track the server's rail state. htmx's global view transitions animate every swap. spec: side — 'left' | 'right' (drives the id, the resize edge, rtl flip) label — the active view's label, shown in the head views — [{ id, icon, label, href, active }], one carousel button each; icon is a Lucide name for the icon() global, href hx-swaps that view's fragment into #rail--body collapseHref? — when present, a close button hx-swaps the whole rail (outerHTML) with the collapsed state the server returns Part macros (head / body / bar) carry their own ids and an `oob` flag: a view-switch response renders the body content (targeted) plus head and bar with oob=true; a stage-driven re-feed renders body + head + bar all with oob=true. #} {% macro head(spec, oob) %}
