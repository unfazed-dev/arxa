{# THE PANEL — one frame for all five panels of a shell. Vocabulary is fixed in ui/common/_integration_panels.md; read it before adding a name here. A shell is built from panels, a panel is built from sections. Macro-only file, so importing it never emits stray markup. HOW A PANEL IS ASSEMBLED. There is deliberately no all-in-one `frame()` macro here. Nunjucks resolves `caller()` to the nearest enclosing `{% call %}`, so a `frame()` that wrapped `{{ caller() }}` could not be invoked from inside another macro's call block without the two callers becoming ambiguous — which is exactly how every panel is written. A single entry point would therefore have been unreachable from the only places that need it, and an unreachable entry point is worse than none: it looks like the contract while nothing verifies it. So a panel writes its own element and composes the sections from the parts below. The element is three lines and belongs to the panel anyway (its role class, its id, its width); what must not be re-invented per panel is the SECTION markup and the id derivation, and that is what lives here: {% import "ui/common/panel.html" as pn %} {% set PID = 'panel-composer' %}

SECTIONS TURN ON BY HAVING CONTENT. `top`/`bottom` render when given content and render nothing when not, so an empty bordered strip cannot be produced by accident. Passing `false` is therefore also how you force a section off when content exists — one truthiness test covers both, which is why there is no separate on/off flag to keep in sync with the content. A full-height strip pinned to one edge; the cursor turns col-resize on hover and the edge lights up in the accent, so the affordance is the thing you actually grab. Three attributes, and the split between them is the point: data-target — the element to resize, BY ID. drag.js resolves it here, so this is a server contract. data-edge — 'start' or 'end'. Which edge you grabbed decides the SIGN of the drag: dragging an end edge rightwards widens the panel, dragging a start edge rightwards narrows it. This is the only attribute that may describe a position, and it describes a position WITHIN a panel, never the panel's own place in the shell. data-persist — the server key to POST the new width to. Absent means the width is client-only and rides the swap; present means drag.js records it. Never a position word. #} {% macro resize(pid, cfg) %}
