{# The inspector pane: the activity panel's 4th view, alongside screens / artifacts / files. What used to be crammed into the overlay card drawn on the screen itself now lives here, at panel width, where it can carry the server-side joins the client cannot see (registry states, kits, flow edges, annotation coverage). Two cards, one at a time — c.inspector.mode picks: element — an element is hovered (transient) or LOCKED (click). The card is the element's own story: role / style / motion / fn, each marked when the server INFERRED it rather than read it off an authored data-attribute (derive+confirm). screen — nothing hovered or locked: the screen the canvas is showing. empty — neither. The lock lives in the session, never in the DOM, so it survives every htmx morph. Hovering while locked changes nothing (the facade returns the same context) — that is what "locked" means. Pinning is NO LONGER what a click does: click locks, and the pin is its own button on this card. It POSTs the same /design/chat/context/element the island used to POST directly, so multi-pick still works — lock one, pin it, lock the next, pin it. Macro-only, so importing it never emits stray markup. Read defensively throughout: every scalar behind {% if %}, every list behind {% for %}…{% else %}, so a viewmodel field the facade has not built yet renders an empty-but-valid pane instead of throwing mid-fragment.
