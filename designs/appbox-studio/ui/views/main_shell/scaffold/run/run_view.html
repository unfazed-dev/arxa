THE ONE DECISION THAT SHAPES THIS FILE (D24): scaffolding is a fast, deterministic, purely local transform of an already-frozen structure.json. No model call, no subprocess, no network, no user input mid-flight. It finishes in milliseconds. Therefore this screen is NOT a progress screen. There is no spinner ring, no stage timeline, no percentage, no live region ticking through steps — and the moodboard's spinner-ring motif is deliberately NOT reproduced here. A progress indicator for a synchronous function call is a lie about where time goes: it invents a wait so the machine looks busy, and it teaches the reader that scaffolding is the slow part of the pipeline when it is the fastest. What a reader actually needs is the opposite of motion: a RECEIPT they can audit after the fact. So every state below answers exactly three questions — what was the input, what landed on disk, and what (if anything) needs a human. Files, deltas and reasons; never elapsed time. Five read states, no sixth "running" one: pre — the gate: frozen input + chosen kits, nothing written yet completed — everything landed clean warning — everything landed, one or more kits carried unmet readiness failed — a write was refused, the run rolled back blocked — the precondition is missing (structure not frozen) No client JS (W1-W6): the only interactions are links and hx-get swaps. ============================================================================ #} {# ---------- the state banner ---------- One line that names the outcome, coloured by severity. `warning` is deliberately NOT red: unmet readiness never blocked this run (D6), it only matters later at deploy, so it reads as a note on a success. #} {% macro banner(c) %}
