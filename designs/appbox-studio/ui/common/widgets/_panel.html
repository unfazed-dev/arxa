{# THE PANEL BASE — the skeleton, implemented once. Vocabulary is fixed in ui/common/_integration_panels.md; read it before adding a name here. A shell is built from panels, a panel is built from sections. The five roles (header · main · activity · composer · footer) are thin instantiations of this file and add no skeleton of their own. Macro-only file, so importing it never emits stray markup. WHY open/close AND NOT ONE `frame()`. Nunjucks resolves `caller()` to the nearest enclosing `{% call %}`, so a `frame()` that wrapped `{{ caller() }}` could not be invoked from inside another macro's call block without the two callers becoming ambiguous — which is exactly how every panel is written. A single call/caller entry point would be unreachable from the only places that need it, and an unreachable entry point is worse than none: it looks like the contract while nothing verifies it. So the base is a BALANCED PAIR. The body streams between the two calls, which also means a body can be an entire canvas without being pre-rendered into a string — the reason the old file already split body()/bodyEnd(). {% import "ui/common/widgets/_panel.html" as base %} {% set P = { role: 'composer', top: head(spec), bottom: false } %} {{ base.open(P) }} …the body… {{ base.close(P) }} Pass the SAME spec to both — `close` needs to know which trailing sections exist. Bind it once with {% set %} and the two calls cannot drift. The pair's one weakness against {% call %} is that it can go unbalanced. That is checked statically: `appbox design lint` (W4) requires the open and close counts of a panel-bound alias to match, per template. spec: role — 'header' | 'main' | 'activity' | 'composer' | 'footer'. A full-height strip pinned to one edge; the cursor turns col-resize on hover and the edge lights up in the accent, so the affordance is the thing you actually grab. Three attributes, and the split between them is the point: data-target — the element to resize, BY ID. drag.js resolves it here, so this is a server contract. data-edge — 'start' or 'end'. Which edge you grabbed decides the SIGN of the drag: dragging an end edge rightwards widens the panel, dragging a start edge rightwards narrows it. This is the only attribute that may describe a position, and it describes a position WITHIN a panel, never the panel's own place in the shell. data-persist — the server key to POST the new width to. Absent means the width is client-only and rides the swap; present means drag.js records it. Never a position word. #} {% macro resize(pid, cfg) %}
