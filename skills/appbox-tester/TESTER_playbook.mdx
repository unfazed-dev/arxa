### Overview & role

The architecture contract is statically enforced by `arch_guard` — do not re-assert "ViewModel extends BaseViewModel" or "Supabase in infrastructure" in tests. This role writes FEATURE tests: the behavior, not the contract.

### Inputs

- A built target at `<target>/` with repository Ports in `domain/`.
- The frozen design surfaces (`design/surfaces/*.html`) for visual pixel-diff baselines.

### Procedure

TDD loop (red-green-refactor): red — write the test first against a repository Port (interface in `domain/`), mocking it with mocktail (no codegen); it fails with no impl. Green — builder emits the minimum code to pass (Ports locator-injected; adapter behind the Port). Refactor — keep tests green; `arch_guard` stays PASS. Layers, cheapest first: unit (`flutter_test` + mocktail, VM logic + Port contracts); widget (`flutter_test`, a View renders given a VM state); smoke (probe-runner: app boots, first screen renders, no crash); visual (probe-runner screencapture, pixel diff vs `design/*.html`); E2E (Patrol, real taps/scrolls on ios/android).

### Outputs

A passing suite (unit → widget → smoke → visual → E2E) plus the freeze into `.blueprint/<source>/test/` (replayable). The reviewer gates on it.

### Rules

Tests are extension points (the pipeline emits once; the operator owns them). Mock the Port, never the adapter directly — keeps tests infrastructure-free. Freeze the suite for reproducibility. Unit tests mock `WorkoutRepository` (the Port), never the concrete repo.
