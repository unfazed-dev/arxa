# appbox-designer — Per-Skill Playbook

`appbox-designer` · status: **active**

**Role (one line):** turn the versioned `intake/registry.json` into the server-rendered htmx app — client JS in the three legal ADR-0009 forms (categorized vendored libs, first-party islands, artifact app modules), genuine MVVM — whose structure the scaffolder transliterates into Flutter.

**Scope of this document:** lets a human OR an LLM drive the design phase without reading the skill source. Folded from `SKILL.md`.

**Pipeline position:** stage 2 — upstream `appbox-intake` (brief + `intake/registry.json`) and `appbox-moodboarder`; downstream `appbox-scaffolder` (FROZEN `structure.json`); a stage-6 review REJECT rewinds here. Full chain, stage numbers, per-stage artifacts: `docs/research/pipeline-map.md` §1.

### Overview & role

The design stage of the pipeline. Every artifact is a Hono + htmx MVVM app (surface = view template + co-located viewmodel) and is the **triad** — prototype, flows, views: three lenses over one view registry, never three artifacts; flows are `{from, to, trigger}` data edges threaded through the data spine. The artifact is a typed input to a build pipeline, structurally isomorphic to `kit/showcase_app/lib` — structure is authored while designing, never back-filled.

### Inputs

A pinned `intake/registry.json` version (full run: every feature) or a frozen run artifact for a registry diff (**delta run**: only the new/changed feature; already-designed features are never regenerated, shared join points are scaffolder-owned and additive-only). The pinned `intake/flows.json` alongside it — with the registry, the only authoring surface: intake elicits/derives + confirms the flows, and the design viewer live-reads AND edits that same file (move/add/remove POST the design server, which rewrites flows.json), never a copy. The design brief when intake produced one — consume its Layout Template verbatim; the compiled commission when a moodboard produced one — SELECTED references and the chosen suitor only, never the raw boards (the boards' "patterns this slice must have" lists remain the per-epic visual bar behind it). The viewport ladder from project config — never assumed, never hardcoded; authoring at phone width only is the single most expensive mistake available here.

### Procedure

Load contracts first: `references/showcase-anatomy.md` (the structure contract), `references/delta-runs.md` (run type + touch scope), `system-prompt.md` (craft SSOT), `DESIGN-ARCHITECTURE.md` (binding data-spine contract), `references/app-architecture.md`, `references/kit-catalog.md` when the brief names kit capabilities, `references/viewport-ladder.md`, `references/harness-tools.md`, `runtime/README.md`; skim `examples/hello-hda/`. Ask (AskUserQuestion) for new or ambiguous work — context, fidelity, variations, output folder, design systems. Set up by copying `examples/hello-hda/` into `designs/<name>/`; import design systems (`appbox design ds-import`) and record deliverables (`appbox design record-asset`). Build widgets-first at the two tiers only — `ui/widgets/common/<group>/` cross-shell, `ui/widgets/<app>_<feature>_widgets/` — with `kind` from the closed 15-kind vocabulary (`starter-partials/widgets/` file list; a kind outside it is a gate failure on both sides, never improvise a mapping). Compose surfaces from the library only, author every rung in the ladder, and let emit stamp the `inspectAttrs` triple and `///` frontmatter. Serve and verify: `appbox design serve <dir> --port 4319` (background) → `appbox design lint <dir>` (ADR-0009 client-JS law: every script resolves to manifest, island, or app module; no inline handlers; declared ceiling enforced) → `appbox lens check` (console clean) → `appbox lens shoot` at every ladder width plus overflow and failed-request checks → `npx tsc -p <artifact>` clean. Fix before surfacing; hand the user the served URL. Productionize on request: `appbox design eject <dir> <out-dir>`.

### Outputs

`designs/<name>/` with `ui/views/*` (base view + `.desktop`/`.tablet`/`.mobile` variants; a multi-section body is a composition widget in the library — `.sections.tsx` files are banned, W1), barreled `ui/widgets/*`, `ui/styles/<owner>/` barrels, the derived `models/screens_model/registry.json` (a projection — regenerated, never edited), the route table the freeze step reads, and the emit-produced artifact-root `tsconfig.json`.

### Rules

`intake/registry.json` is the only authoring surface — never author a second source of truth. Locked laws: vocabulary (hub > shell > view > widgets; "screen"/"page" banned as structural nouns), filenames (no leading `_`, no version/era prefixes), styles (`ui/styles/<owner>/` only, one barrel per folder, `base.tsx` links barrels and nothing else), widget barrels, exactly one application hub per app, the two-tier widget placement law, the W9 view-composition law (view templates are Capitalized widget invocations only — ANY raw HTML element in `ui/views/**`, structural wrappers and slot outlets included, fails lint even with `data-el` identity; identity markup lives inside widget files), named islands only. Layout values are kit constant names (`abxPad*`/`abxGap*`/`abxHug`/`abxFill`…), never raw numbers — an off-ladder value is a request to add a kit constant. You compose; you never resolve — `widget: null` means composed; name the variant and author the recipe. Auto Layout default-ON (`data-layout`, `data-resize-x/y`, `data-layout-ignore` to exempt). Localized artifacts keep every string in `l10n/app_<locale>.arb` rendered via the `t` prop, and `appbox design pseudolocalize` runs before handoff. Artifacts stay self-contained (assets copied in; vendored SRI-pinned libraries only). The runtimes are Dart — run `appbox design doctor` to preflight.

### Behavioral conformance (replica craft)

When the commission is "replicate this reference", visual section parity is the floor, never the audit. Postmortem ground (energize client repo, coffee-tech replica, 2026-08-18): the artifact shipped section-exact AND DOM-exact while four behavior systems were absent or mis-scoped — cursor follower, SPA view transitions, loader/curtain scope, smooth-scroll boot; ledgers at `landing/design/energize-landing/evidence/conformance/{cursor,transitions,scroll}/VERIFY.txt`.

**Audit doctrine.** A capture samples one settled cell of a larger machine. Four blind classes, none visible in any screenshot: **input pipelines** (wheel/touch/pointer/momentum — stills neither scroll nor hover), **boot gating matrices** (width × pointer × audit-browser × sessionStorage × load-type — behavior differs per CELL, a capture is one cell), **global chrome** (cursor, transition containers, loader curtains — mounted at body level, owned by no section), **session flags** (cleared by hard reload, never present in the DOM). Why each postmortem system hid: the cursor's state visuals are computed `::before` content, not pixels at rest; transitions exist only between states (0.7s wipe visible only mid-flight, clip-path sampled in motion); curtain scope is a load-type gate every settled capture has already passed; the scroll gap lived in a boot band nobody emulates (touch at width >768 — neither the phone path nor the desktop path). **Law: section-exact ≠ behavior-exact, and every missed system was cross-section.** A behavior audit therefore ships what screenshots cannot: the gating matrix as a written artifact (every cell a claim, empty = unknown, not negative), synthetic-input probes, and source ports for unobservable references.

**Pre-flight checklist — any "replicate this behavior" commission:**

- **Enumerate input pipelines** (wheel, touch drag + momentum, hover/move/click, keyboard) with arithmetic stated BEFORE measuring — wheel deltaY 500 must settle at exactly 400 under a ×0.8 engine; a 50px touch drag targets 125 under ×2.5.
- **Build the gating matrix**: width (≤768 / >768) × pointer (mouse/touch) × audit-browser × session keys × load-type (full / SPA commit / popstate). The matrix is the audit artifact, not scratch.
- **Inventory global chrome vs section content**: cursor, curtain, header behaviors, transition containers — mounted outside sections. Decide curtain/loader scope from SOURCE, not from one observed load (their head-init comment: "Orange opening loader on every full page load / refresh (all pages)" — no session skip, only the header fade session-gated, SPA transitions suppressing repeats).
- **Diff session-storage and window flags**: every key the reference reads, who writes it, what a hard reload clears. **A flag read but never written is a port gap** — the engine polled `window.__cftViewportHeightLocked`, nothing set it, and every touch device >768 spun in the boot wait forever, silently degrading to native scroll.
- **Inventory lifecycle contracts**: window teardown handles (`window.cleanupCursor`), re-init events (`pageReady`), refresh calls (`ScrollTrigger.refresh` at rAF+100ms) — SPA re-init double-binds without them.

**The unobservable-reference law.** References may self-disable under audit browsers (coffee-tech's `__cftIsAuditBrowser` undefines its scroll engine in headless — absent under the lens while the source plainly ports it): the live reference is unobservable BY DESIGN, and "broken in headless" is evidence of a gate, not of absence. Protocol: save the reference bundle → byte-diff the live copy against the saved copy (re-verify same day) → port verbatim, divergences documented in the module header → measure the REPLICA live (it carries no audit gate). Parity = identical source + measured replica behavior, never "looks right in a capture".

**Proven instruments** (lens-safe): synthetic wheel/touch never scroll natively — only a JS engine responds (dispatch, sample scrollY at 80/380/1000ms, assert the arithmetic); synthetic mouseenter/leave/click drive hover machines (assert `classList` + `getComputedStyle(el,'::before').content` + transform); SPA probes (window-flag survival = no reload, mid-flight `.transition-container` clip-path, pushState pathname, popstate); curtain t0/t1 probes; touch simulation = set `window.ontouchstart` (null suffices — mere existence flips detection) then dynamic-import an unguarded module export; expect scripts that return an object exit 1 printing `(got {...})` — true is the only pass, the object IS the readout; when animated lens capture crashes (known Infinity bug in the appboxd lens), use record/burst/settled-state stills + expects; parked captures asserted via vision tools with ABSOLUTE paths.

**Wiring placement (ADR-0009).** One system per artifact app module — `assets/app/*.js`, named, headered, lint-resolved (`cursor.js`, `transitions.js`, `smooth_scroll.js`, `loader.js`, `chrome.js`), with `app.js` owning boot call-order to mirror the reference's script-eval order. The viewport lock (`--vh` = 0.01×innerHeight on html+body + flag; re-measure on width-change resize, orientationchange +200ms) is called at script eval, component init, AND every SPA commit — missing one strangles a gated engine. The SPA commit sequence lives in `transitions.js`: wrapper swap in place, title/lang sync, cursor cleanup + re-init, `ScrollTrigger.refresh`, link re-wire, `pageReady` dispatch, viewport re-lock; error path falls back to `window.location`. CSS-state-driven visuals stay in the sheet — JS toggles state classes, `ui/styles/` carries the visuals (`::before` labels, transform transitions), making computed `::before` content the assertion surface; state machines with no visual carry inert classes, ported as-is. Every global system keeps a window cleanup contract (teardown semantics preserved even when registries collapse). Evidence lands per system at `evidence/conformance/<system>/VERIFY.txt` — the parity ledger: verified-from-source / verified-live / ASSUMED / divergences, one capture per claim.
