# Server-first HDA runtime (Hono, skill-vendored)

Porting appbox-designer to htmx+CSS forces a runtime decision: htmx talks to endpoints, static hosting kills POST/query-param/session state, and `file://` kills htmx requests entirely. We decided every Artifact runs on a small hypermedia server — the skill vendors one Hono/Node Runtime plus a Serve CLI — accepting a runtime process per artifact in exchange for full fidelity (real verbs, cookies, sessions, query-param deep links, server-driven timers). Considered and rejected: pure static GET-only (degrades countdown, cross-view persistence, POST flows), static + opt-in micro-server (two architectures to document and maintain), Python runtime (dropped when the user committed to Hono end-to-end — one language for prototype and productionize).
