# Server-owned State Playbook

One mutable store: the server. DOM is a projection; URL is shareable state; cookies carry small scalar prefs (<4 KB: theme, accent, role); a session store carries multi-step flows; OOB swaps fan updates out; timers use load-polling — the server holds the deadline and renders `deadline − now` per tick, dropping the trigger or answering 286 at zero (SSE reserved for multi-viewer or sub-second cases, since boosted navigation kills per-page streams). Theme/accent changes POST to a cookie-setting endpoint answered with `HX-Refresh`, and CSS vars render inside body content — body/html attributes do not update under boosted innerHTML swaps. Considered and rejected: SSE-first timers (per-page stream lifecycle under boost), CSS `:has()` client state machines (no cross-page persistence), client-side-templates as the primary data path (inverts the HDA architecture).
