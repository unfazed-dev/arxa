`appbox-story-mapper` · status: **active**

### Overview & role

The story-mapper elicits; it does not generate (architecture §22) — no views, viewmodels, routes, or layouts; the map is the client's words, structured. With intake answers the emitted brief is **unified** (intake sections first, then Releases, hierarchy, surface inventory); standalone (intake is optional, plan 10.7) features derive surfaces as before, flagged ` — [inferred]`. The mapping is enforced by the emitter, not prose: Epic→shell (slug = the name's first ascii word, lowercase), Feature→surface (`id = <epic-slug>.<feature-slug>` matching `^([a-z][a-z0-9]*)\.([a-z][a-z0-9]*)$`), Story→requirement listed under its feature, MoSCoW + release rolled up per surface (strongest live priority, earliest live release), all-`wont` features → Out of scope.

### Inputs

Product requirements from the user — project name, 2–8 epics, 1–6 features per epic, 1–10 stories per feature, priority (must/should/could/wont) and release per story; optional points, description, locales + default locale. Optional intake answers: `--answers`, auto-discovered from `pipeline/state/run.intake.json` then `pipeline/state/default.intake.json`.

### Procedure

Gather per the conversation guide (opening → per-epic walkthrough → confirm priorities → confirm releases), building the JSON per the SKILL.md field reference (`releases[].name` must match each story's `release`; `priority` is validated). Emit one command — `appbox emit story-map --input data.json --output docs/design/story_map.html --data-out docs/design/story-map.json --brief-out docs/design/brief.md` (stdin without `--input`; add `--answers` when chaining). Self-check with `appbox emit story-map --self-test` (slugs, gate parse, all-wont rule), then `appbox gate intake` for registry↔brief traceability both ways. Hand off: `brief.md` + `story-map.json` to the designer, `story_map.html` to the client for scope confirmation; optionally `appbox intake seed --brief docs/design/brief.md`.

### Outputs

`docs/design/story_map.html` — self-contained interactive map (three-tier cards, MoSCoW colors, release swimlanes, stats panel); `docs/design/story-map.json` — the full-fidelity machine handoff (priorities, releases, points); `docs/design/brief.md` — the unified brief with provenance-marked intake fields (`client`|`founder`|`inferred`, `inferred` visible), `## Surface inventory`, and `## Layout template` when elicited.

### Rules

With answers, the surface inventory IS the intake-declared surfaces: features pin by explicit `id` equal to a declared surface id, and only unmatched derivations are flagged ` — [inferred]`. This skill never binds a `surface` to registry entries — intake names; the designer binds. CJK-only names slug to `s` — prefer readable slugs and confirm derived ids with the user before emitting. Over 50 stories → consider splitting into sub-maps. Keep the standard layout (all three artifacts under `docs/design/`) so `appbox gate intake` needs no flags.
