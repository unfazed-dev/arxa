# app-box-scaffolder — Per-Skill Playbook

`app-box-scaffolder` · status: **active**

**Role (one line):** turn a FROZEN `structure.json` + target set into the per-surface Flutter file set the coverage gate asserts — form factors follow targets, never empty.

**Scope of this document:** lets a human OR an LLM drive the scaffold engine without reading the skill source. Folded from `SKILL.md`.

### Overview & role

The scaffolder PRODUCES the tree the gates ASSERT (architecture §16). The structure gate checks the authored layer against `structure.json`; the coverage gate checks the scaffolded layer against `structure.json` + targets. This skill is the missing producer between them — the one the P14 dogfood named (14.8 / honest-bar #2): until it existed, no tool turned a frozen design into the Flutter file set, so "scaffold D1" and "coverage of D1" had no target. It is the inverse of the structure gate: where that gate asserts the tree matches the registry, the scaffolder emits that tree. It emits STRUCTURE only — minimal valid Dart skeletons carrying the class name the builder (plan 08) implements; the widget bodies are not this skill's concern.

### Inputs

- A **frozen** `structure.json` at `<design-dir>/structure.json` (produced by `tools/emit_structure`; the scaffold reads it as frozen input and never re-derives structure).
- A **target set** (`--targets macos`, or `ios,android`, or `web`, …) — explicit, never ambient. Every target must have an entry in `pipeline/state/targets.derivation.json`.
- The derivation table (`pipeline/state/targets.derivation.json`) and config viewports (`config/app-box.config.json`) — the source of factor names and ordering (P06/R3). The scaffold reads these; it does not hardcode them.

### Procedure

Confirm the design is frozen (`emit_structure.py --check` in sync). Scaffold, naming targets explicitly: `python3 skills/app-box-scaffolder/scaffold.py --design-dir <design> --app-root <app> --targets macos`. `--targets` is required (or `APPBOX_TARGETS` env); the scaffold never reads ambient pipeline state for targets (the stale-green defect, §16). Widths and factor names come from the derivation table + config, never literals (R3). Verify drift after a registry edit with `--check`: it regenerates the expected set in memory and diffs against disk, naming any missing factor file, stale manifest, or hand-edited dir — the same file set `gates/coverage` (C1) walks. Hand the scaffolded tree to `app-box-builder` for the widget bodies; the coverage gate then asserts the scaffolded layer.

### Outputs

Per frozen surface (those with `surface` non-null in `structure.json`), under `<app-root>/lib/ui/views/<shell>/<tab>_<short>/`: `_view.dart` + one `_view.<factor>.dart` per **derived** factor + `_viewmodel.dart`. `macos` → 3 files/surface (desktop only); `ios,android` → 4 (mobile+tablet); `web` → 5. Excluded surfaces (`surface:null`) are not scaffolded. Plus `lib/ui/views/.shell-structure.json` — the manifest the coverage gate reads (`selfContained` + the `{shell: {surfaceId: dir}}` map). The directory name is `<tab>_<short>` from the registry id (the stable key, §18), recorded because the coverage gate refuses to guess it.

### Rules

Form factors follow targets — never emit an empty `.mobile`/`.tablet` to satisfy a count; that is the stale-green pattern §16 exists to kill (the self-test guards it). Never hardcode widths or factors — they come from the derivation table + config (P06/R3); adding a target is a data edit, not a code change here. Never read targets from ambient state — pass `--targets` explicitly. Never edit scaffolded Dart directly — edit the authored layer, re-freeze, re-scaffold, or the drift check dies. Treat stub bodies as unfinished — the builder replaces them. Keep `scaffold.py --self-test` green when you change the engine; it is the proof the guardrail holds (negatively: missing structure.json, surface with no viewmodel, wrong file count, unknown target, dir collision; positively: macos→desktop only with no empty factors).
