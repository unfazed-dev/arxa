# appbox-lint — Per-Skill Playbook

`appbox-lint` · status: **active**

**Role (one line):** health-check the knowledge base — catch contradictions, stale claims, dead links, orphan pages, and docs that disagree with shipped code/catalogs.

**Scope of this document:** lets a human OR an LLM run a docs-consistency pass without reading the skill source. Folded from `SKILL.md`.

### Overview & role

The expensive failure isn't a missing doc — it's a confidently wrong one. A single un-caught contradiction propagates into memory, handoffs, and changelogs while contradicting the catalog's own rules, and costs a round-trip. Lint exists to catch that class of rot: a mechanical pass (a script, cheap, deterministic) and a semantic pass (you, reading — judgment the script can't do). Run both.

### Inputs

- The knowledge base: `docs/` (prose), catalogs (`*.json`, enforced runtime truth), cross-session memory, and the relevant code comments.
- The source-of-truth hierarchy (`docs/KNOWLEDGE.md` or equivalent).

### Procedure

Mechanical pass — run `appbox docs` (the Dart port of the archived `lint_kb.py`): flags docs missing from the index, dead `.md` links, orphan pages, half-wired supersede pointers, unresolved memory wikilinks; exit 1 = at least one error; fix errors before continuing. Semantic pass — for each topic touched recently (read the last few changelog entries), cross-check the claim across all layers (catalogs ↔ docs ↔ memory ↔ code comment) and find disagreement. Resolve per the hierarchy: the lower layer is the bug; fix the doc/memory to match the catalog/code, never the reverse unless primary-source-verified. Record it: append a changelog entry; when a claim is superseded, leave a one-line `⚠️ SUPERSEDED by (y)` pointer and write the new entry — append-only, never rewrite history.

### Law pass — liquid-glass & M3E (ratified 2026-08-13)

App/kit code must agree with the platform laws the same way docs must agree
with catalogs. SSOTs: `docs/liquid-glass-allowlist.md` (THE liquid-glass
law) and `docs/m3e-law.md`. Kit-side the law is enforced by
`appbox_kit_liquid_glass_law_gate_test.dart` + the transition gate; this
pass extends the same checks over app code (showcase + scaffolded apps).
Mechanical greps, each hit guilty until a `// glass-law-exempt: <reason>`
names why:

1. **saveLayer over platform views** — `BackdropFilter(|ImageFiltered(|ShaderMask(`
   in any file that also references `AppBoxKitNative*`/`CN*` widgets or
   whose subtree hosts them (law rule 1).
2. **Alpha over native** — `Opacity(|AnimatedOpacity(|FadeTransition(`
   wrapping native-glass subtrees; motion must be slide/transform.
3. **Hand-assembled top chrome** — `Scaffold(` with an `appBar:` in a file
   that ALSO puts native glass controls in scrollable content; the chrome
   scaffold (`AppBoxKitChromeScaffold`) is the only lawful assembly
   (law rule 4). Nested pushed-route Scaffolds with a boxed bar are lawful.
4. **Glass-on-glass overhang** — fixed native glass (a `LiquidGlassContainer`
   or CN control positioned as chrome) overlapping the travel path of
   in-scroll native glass (law rule 5; the title pill precedent).
5. **M3E shape discipline** — new M3E chrome must repeat the
   transparent-container + own-unrounded-Material fix and gate on
   `wantNative && supportsComposeM3E`, never bare `Platform.isAndroid`
   (M3E law rules 1–2).

### Outputs

A green mechanical pass plus a list of semantic corrections applied (each with a changelog entry). Note gaps the lint can't fix: a concept lacking a page, a plan whose status is unverified, a catalog that may be stale.

### Rules

Run the law pass whenever the touched code renders UI — the laws are
catalogs in the hierarchy sense (they enforce; prose lags), and a law
violation in app code is the same class of rot as a doc contradicting a
catalog. Don't trust memory or a doc over a catalog/code — catalogs enforce, prose lags; on conflict the prose is wrong. Don't rewrite the changelog — supersede with a pointer + new entry. Don't fix only the file you noticed — a wrong claim usually lives in 2-3 places; grep the assertion across all layers and fix every copy. Don't skip the semantic pass because the script went green. Keep `appbox docs` (the Dart docs_lint — `appboxd/lib/docs_lint.dart` + `appboxd/test/docs_lint_test.dart`) green when you change it.
