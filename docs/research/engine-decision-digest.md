# Engine / Memory / Payment — decision digest

Digest of prior research, load-bearing for three upcoming efforts. Format per
`README.md`: claim — source — why it matters. Digested 2026-07-30.

## ENGINE (appboxd gateway + stage-runner + model fabric)

- **appboxd is already decided: pure-Dart daemon holding credentials in the OS vault, executing pipeline phases/gates** — `docs/plans/consolidate-one-app-plus-daemon.md` — the engine builds *inside* this settled shape; no re-litigating host/daemon topology.
- **E1/E2: vault keys only in appboxd; loopback gateway serves OpenAI- and Anthropic-compatible endpoints with scoped per-consumer tokens** — `docs/plans/appbox-engine-llm-fabric.md` — the gateway contract is already written; engine build is implementation, not design. Kimi CLI takes `base_url`+config; Claude Code takes `ANTHROPIC_BASE_URL` (both A-grade).
- **Deterministic stage-runner, not an LLM commander** — `docs/plans/appbox-engine-llm-fabric.md` — MAST (1600+ traces): task-routing errors and error propagation are the top multi-agent failure modes; multi-agent burns ~15× tokens. The pipeline is a workflow, so gates drive escalation, not judge models.
- **Gate pass/fail IS the reward signal for stage→model affinity (Fugu inheritance)** — `docs/plans/appbox-engine-llm-fabric.md` — no trained router needed; scorecards tune the tier map at zero training cost. Feeds directly into MEMORY.
- **Dogfood lesson: the producer-shape seam was the single blocker — freeze/coverage gates were wired for the stacked_kit producer, not the htmx producer D1 emits** — `docs/research/dogfood-report.md` (honest-bar #1) — stage-runner must treat producer-contract mismatch as a *precondition*, not let gates fail mysteriously at render time. Closing it took the P09 engine + explicit shape detection.
- **Dogfood lesson: human gates halt and mint nothing; `--approve` is the only stamper; adding a target after approval invalidates the stamp loudly** — `docs/research/dogfood-report.md` (14.14/14.15) — the engine's stage-runner must preserve this: approvals are human-minted, target-stale is loud. Consolidation extends this: any authenticated shell can mint, agents structurally cannot (provenance-bound records).
- **Dogfood lesson: green-over-broken is the failure class to guard against** — `docs/research/dogfood-report.md` (honest bar) — scaffold vacuous PASS, coverage C4 green-on-nothing, R5 guard grepping the wrong file. The engine embedding these gates inherits all three traps; guard and gate must be checked in the same file.
- **Stub: payments and auth are the two real holes (Stripe/PayPal/Apple/Google sign-in all throw)** — `docs/research/stub-inventory.md` — engine work is unblocked (design→freeze→scaffold→deploy all wired), but don't sequence anything onto kit payments/auth.
- **`hasSkill: false` on all 23 kits; flutter-crew is the only stage-contract prior art** — `docs/research/stub-inventory.md` — the stage-runner's skill format has no in-kit template; flutter-crew's contract (plus the decided Markdown-Agent-Skills standard, E3) is the reference.
- **genui facts: appboxd-as-A2UI-server topology proven (`verdure` example + local spike); mock seam is `A2uiTransportAdapter(onSend:)`+`addChunk()`** — `docs/research/flutter-genui.md` — this is the daemon injection point; spike confirmed chunk reassembly, surface buffering, custom catalog items.
- **genui risk is structured-output reliability of the chosen model, not the framework; genui is pre-1.0 (0.10.1), renames expected, ~65–70 transitive packages** — `docs/research/flutter-genui.md` — the fabric's `param_policy` + validate-and-repair loop (E4/bridge notes) exists precisely because provider structured-output modes differ and move.
- **Per-provider protocol quirks are already cataloged (Kimi: omit temperature/json_object only; Anthropic: no OpenAI shim; DeepSeek: echo `reasoning_content` or 400; z.ai PAYG vs Coding Plan)** — `docs/plans/appbox-engine-llm-fabric.md` — adapter work is enumerated, not discovered; flagged-unverified list (Gemini prices, z.ai Anthropic endpoint, Kimi env var, Fugu pricing) must be re-checked at build time.
- **macOS entitlement gap: appbox lacks `com.apple.security.network.client`** — `docs/research/flutter-genui.md` + `docs/plans/consolidate-one-app-plus-daemon.md` (Open) — required the day appboxd is reached over HTTP, *localhost included*. Cheap to forget, breaks the first gateway call.
- **Deploy is wired for fastlane/shorebird/CF Pages; `VercelTarget` throws** — `docs/research/stub-inventory.md` — engine stage-runner must not advertise/schedule vercel.
- **Targets must be explicit on gate/golden runs, never ambient** — `docs/research/web-research-drift.md` (flutter-crew correction) — the engine passing targets from pipeline state into gates must pass them as flags, or reproducibility depends on ambient state (the `dep_hash` stale-green defect class).

## MEMORY (scorecards, lesson logs, facts, drift handling)

- **The repo's own answer to "research goes stale": leave falsified claims in place with corrections appended, don't edit them out** — `docs/research/README.md` — memory records corrections as new facts superseding old ones, never silent mutation. Both `web-research-drift.md` (§11 correction) and `flutter-genui.md` (spike corrections section) follow this.
- **`generate && fail-on-diff` with **porcelain, not `git diff`** — `docs/research/web-research-drift.md` — `git diff --exit-code` misses untracked files (green while broken); porcelain catches both. Any memory/state file the engine regenerates must be gated this way. Dogfood 14.13 proved porcelain drift detection works and names the offender.
- **Diff-based drift detection has ~30% recall** — `docs/research/web-research-drift.md` — semantics can move without the artifact moving; pair diff checks with execution/coverage assertions. A memory system asserting "state unchanged" from diffs alone is a 30%-recall instrument.
- **Spec-driven dev's known failure: authority is convention, not enforcement** — `docs/research/web-research-drift.md` — memory (scorecards, lessons) is only durable if a gate consumes it; an unenforced lesson log rots. This is the same gap as "structure.json exists" vs "structure.json is gated".
- **Scorecard schema already decided: `{stage, tier, provider, model, tokens_in, tokens_out, cost, gate_pass, retries}` appended to pipeline state per run; routing-regret = per-stage gate-pass-rate per tier** — `docs/plans/appbox-engine-llm-fabric.md` — the MEMORY system's primary fact table is specified; build to this shape. Regression suite (~20 representative specs) precedes any tier-map change.
- **`TODO(prose)` pattern: the generator marks its own gaps and `test_memory.sh` asserts the count is zero** — `docs/research/stub-inventory.md` — direct prior art for memory self-auditing: emit explicit markers for unwritten lessons and a test that counts them.
- **Dogfood lessons that should become durable memory** — `docs/research/dogfood-report.md` — (1) gates must name the offender in output; (2) a gate that cannot fail is not a gate (R5, and the R5 guard itself false-negatived by grepping the wrong file); (3) human gates mint nothing automatically; (4) approval stamps invalidate loudly on target change; (5) transient state (`.kit/`) must be gitignored/lint-exempt. Each is a scored, evidence-backed lesson — exactly the lesson-log payload.
- **Freeze error-inflation bug class: per-(surface, viewport) fresh page, or handlers accumulate (~4× error counts)** — `docs/research/dogfood-report.md` (14.7) — memory lesson: stateful listeners accumulate across iterations; any long-lived engine process re-running stages needs fresh handler registration per run.
- **flutter-crew smell: `test.bak/` duplicating five test files verbatim** — `docs/research/stub-inventory.md` — memory/hygiene lesson: dead copies beside live ones make suites lie about coverage. Fact store must not accumulate unversioned duplicates.
- **Human-gate provenance records are already specified: shell type, WireGuard node identity, confirm method, timestamp, design/build hash** — `docs/plans/consolidate-one-app-plus-daemon.md` (#6) — approval records are a memory subsystem with a fixed schema; build once, reuse.

## PAYMENT (encrypt artifacts + license unlock)

- **Model settled: licence-only, flat, never per-seat, BYO-key; paywall at first deploy** — `docs/plans/consolidate-one-app-plus-daemon.md` (#11, amends architecture §17) — design→prototype→build→gates→preview all free; you pay when you ship. The licence precondition lives in the deployer — the only phase that writes to the outside world.
- **BYO-key is a structural cost advantage, not a discount: inference cost is the user's** — `docs/research/competitors-and-pricing.md` — argues flat licence over usage metering; undercutting FlutterFlow is the actual cost structure, not a loss-leader.
- **The loudest market complaint is per-seat pricing** (FlutterFlow Business $150/seat vs Adalo $200/10 seats; 5-person team pays $350/mo) — `docs/research/competitors-and-pricing.md` — validates never-per-seat; agencies (persona P5) are exactly the enraged buyer.
- **Free tier = full product on LAN with 1–2 active projects: "not crippled, merely smaller"** — `docs/plans/consolidate-one-app-plus-daemon.md` (#11) — constrains the encryption design: the free tier must be the *whole product*, so encryption/licensing gates deploy+scale, not features. Michelle's trial is the product.
- **FlutterFlow's one-way export trap is the failure app-box positions against; code download requires a paid tier** — `docs/research/competitors-and-pricing.md` — tension to manage: encrypting generated artifacts must not recreate the export trap we're positioned against. The unlock must feel like Shorebird-annual (generous timing), not FlutterFlow (ransom).
- **Shorebird design lesson: flat annual with everything credited upfront beats discounting** — `docs/research/competitors-and-pricing.md` — solving a grievance (expiring credits) by changing *when* allowance lands costs nothing under BYO-key. Candidate licence shape.
- **No working card processor in stacked_kit: Stripe + PayPal both throw; Apple Pay is the only wired path** — `docs/research/stub-inventory.md` — the licence-unlock mechanism has **no payment foundation in the kit**; licensing must run outside the kit or Stripe gets implemented (`flutter_stripe` per the kit's TODO). This is the biggest open gap for PAYMENT.
- **Auth providers also stubbed (Apple/Google sign-in throw; SeedAuthBackend stub)** — `docs/research/stub-inventory.md` — licence activation typically wants account identity; no kit auth exists to bind a licence to.
- **O2 (price point) remains open** — `docs/plans/consolidate-one-app-plus-daemon.md` (Open) — model settled, number not chosen. Reference points on file: Lovable $25/mo flat, Cursor $20/seat, FlutterFlow $30–70/mo.
- **No Totem Cloud at launch; self-host (docker-compose headscale) or hosted Tailscale** — `docs/plans/consolidate-one-app-plus-daemon.md` (#10) — no recurring-revenue service exists to entitle licences against at launch; licence verification must work offline/LAN (daemon-local validation), which shapes the crypto (signed licence file, not a license-server call).
- **Vendor price claims were independently checked ~2026-07-19 and flagged to re-verify before quoting customer-facing** — `docs/research/competitors-and-pricing.md` — pricing facts are perishable; MEMORY should carry the checked-date with each.
