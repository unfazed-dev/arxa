Mechanism

Inside the Hub

One send() lands on a hot command channel — execution, state, and routing are already subscribed.

Command channel

  • PublishSubject(sync: true) — the run starts inside the send() call, so a same-frame double-tap always meets the guard.
  • Re-entry guard — a second send while in flight never re-runs; its handle completes with the in-flight result.
  • debounce drops events, never callers — superseded handles complete with the eventual run.
  • throttle is leading-edge, window anchored at run start.

Execution

  • The op runs hot — awaiting the returned Future is optional; dropping it is harmless (errors pre-observed, never unhandled).
  • retry re-runs the attempt factory with backoff; timeout applies per attempt.
  • flushOnDispose — a pending debounced send executes on dispose: the last write always lands (autosave).
  • Disposed hub stops accepting sends; in-flight ops run to completion (cooperative-only).

Routing out

  • state$ — seeded BehaviorSubject of busy + last error; views bind it with ArxaKitStreamBuilder.
  • errorMessage — swallow + fallback value; unset, the handle rethrows.
  • loading · success · errorNotification — routed to snackbar, dialog, or bottomSheet.
  • onError · onSuccess · onSend — side-effect taps at each transition.
owner-scoped — created lazily by ArxaKitActionOwner, dies with the ViewModel async_redux dispatch / dispatchAndWait model

The Verb Map

Commands out

// register once, send many late final _save = abxActionHub.on<Note, void>( 'save', (note) => _repo.put(note), errorMessage: 'Could not save', ); Future<void> save(Note note) => _save.send(note);
// one-shot, no long-lived op abxActionHub.send('pin', () => _repo.patchNote(o, p)); // facade writes — one policy door mutate(() => _repo.patch(o, p), name: 'pin', entity: note.id, error: 'Could not update');

patch for existing rows, upsert for creates. patch writes only the columns that changed — a concurrent edit to any other column survives.

Reactions in

// repository — the data sources watchAll(query) · watchById(id) // facade — derived, composed Stream<Note?> note$(String id)
// viewmodel — side effects only listen( 'note.sideEffects', to: [_notes.note$(noteId)], onData: (note) => _onNote(note), ); // view — binds streams directly ArxaKitStreamBuilder(stream: vm.note$)

watch names a data source, listen names a side effect — Riverpod's codified split, applied to the whole layer stack. The view never listens; it binds.

state$ · actionState$(name) — busy + error as a seeded stream dispose is automatic with the owner
