# studio-v2 boot-sequence wiring — grill rulings 2026-08-13

Request: wire hub + shells in proper sequence — startup shell boots (showcase-app
style), routes to the application hub, hub hosts stage shells (dashboard, intake,
design) behind guards; auth shell designed later.

## Rulings (each confirmed by the user, one at a time)

- **R1 — the hub owns `/`.** No `/hub` route name exists. An un-booted session
  hitting `/` is bounced to `/startup`; boot-complete proceeds back to `/` where
  the hub frame renders with a hosted stage inside.
- **R2 — flat routes, hub-composed.** Dashboard keeps a real route `/dashboard`
  (intake `/intake`, design `/design` when they land). `/` = hub frame + default
  stage (dashboard). Every hosted route renders the same hub frame with that
  shell in the body outlet — one frame, hx-boost swaps. Registry stays
  one-route-per-surface.
- **R3 — boot guard covers all hub-hosted routes, with return-to.** Un-booted
  hits on `/`, `/dashboard` (later `/intake`, `/design`) redirect to
  `/startup?to=<target>`; proceed lands on the validated target (default `/`).
  Ceremony surfaces (`/unknown`, later `/auth`) are never boot-guarded.
- **R4 — hub gets a registry entry; guard-as-data for auth.** New entry
  `studio_application_hub.hub`, `shellKind: "hub"`, route `/`; hosted stages gain
  the registry `tab` field (tab order = registry order). Auth guard lands as
  data only: `requiresAuth` + flows edges marked pending-shell; **no** routes or
  redirect stubs for unbuilt shells (Q-v2-5 stance holds).

## Mechanics

- Boot state is prototype-grade structure: `POST /startup/proceed` sets
  `studio_booted=1` cookie (Path=/, SameSite=Lax) and HX-Redirects to the
  validated `?to`. The guard is a server-side wrapper in `app.routes.js` backed
  by `ui/common/boot_guard_viewmodel.js`; `?to` validates against the hosted
  roster — anything else collapses to `/` (no open redirect).
- `shellRoots` gains `studio_application_hub: '/'`; dashboard moves to
  `/dashboard`; `GET /` and `GET /dashboard` render the same hub-framed
  dashboard (default hosted stage).
