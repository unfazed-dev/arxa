## Architecture

Two planes, one store row.

### Application plane (artifact-owned)

- `assets/app/palette.js` — owns `html[data-palette]`, meta theme-color,
  localStorage memory, `?palette=` override, the `arxa:palette` broadcast,
  and (in static mode) the remote published fetch. Exposes
  `window.__arxaPalette` — the dial calls `set()`; PUBLISHING is never its
  job.
- `assets/styles/palettes/` — generated override sheets +
  `_template.json` (the pre-indexed color slots the server derives pasted
  palettes from; regenerated by `evidence/rebrand/genpalettes.mjs`).
- `palettes.json` — the declaration manifest (ids, names, swatches,
  themeColor, seeded, sheets). Consumed by the design server (serve-time +
  dial config), the eject bake, and palette.js (theme-color SSOT).

### Publication plane (dial-owned)

- `design_palettes.dart` — manifest loader, serve-time attribute
  (?palette= > stored > default), Coolors slug parse, lightness-rank roles,
  the transplant derivation (dh additive, saturation ratio capped
  [0.3, 1.3], dL additive — mirror of genpalettes.mjs), ingestion (sheet +
  tokens block + manifest, dedupe by swatch set, delete strips all three),
  and the `DeployedDialBake` resolver.
- `design_axes.dart` — `AxesPick` gains the nullable `palette` axis;
  store reads/writes `arxa_dial_axes.palette` (migration ADDENDUM 17).
- `arxa_dial.dart` — POST /__dial/axes accepts palette-only picks, validates
  manifest membership, guests publish palette ONLY (style/theme stays
  author-only); POST /__dial/palettes (+/delete) author-only.
- `design_server.dart` — axes store gates on app-kind OR palettes.json;
  serve seam applies axes + palette; one axes config block
  `{styles, themes, palettes, active, published}`; SSE broadcasts `axes`
  (pick) and `palettes` (list) frames.
- The island (arxa-dial.js) — 2-slide tray; Theme slide renders palette
  cards (swatch strips), publishes author+guest (Q9), mirrors the SSE laws,
  Coolors paste row (author, non-static), delete × (author, unseeded).

### Deployed static channel (Cloudflare worker)

- Eject bakes `ARXA_PALETTES` + `ARXA_DIAL_STATIC` into worker.js
  (publishable key only), copies `arxa-dial.js` + `supabase-js.min.js`,
  and mints/reuses the author token (env `ARXA_DIAL_AUTHOR_TOKEN` wins;
  hash stored on `arxa_dial_designs.author_token_hash`).
- The worker stamps `data-palette` (?palette= > baked published > default),
  serves /palettes.json, injects `window.__ARXA_PALETTE__` remote config,
  and injects the dial ONLY when `?dial=` / `?dial-author=` is present
  (author hash-verified worker-side).
- The island's static driver: `api()` reroutes to PostgREST (pins/replies
  mirrored from SupabaseDialStore's shapes), publishes via
  `publish_palette` RPC, validates guests via `resolve_guest_link` RPC,
  saves the live overlay via the `save_overlay` RPC (edit redesign,
  2026-09-11), subscribes Realtime (pins/replies/axes/overlays; the drawings
  channel retired) into the existing SSE-frame handlers, and degrades
  design-time endpoints (ship/media/roster) to clean local refusals. No
  credential = no dial.

## Addendum — the edit redesign (grilled 2026-09-11, nine decisions)

The over-built inspector DIED: editing is **text + image swap** on the
canvas (double-click to type; click an image → chip → swap), everything
else — style facets, CSS escape hatch, resize handles, the arxa-studio
tab, the draft ledger, the server-side undo journal, the
`/draft /commit /undo /redo` routes — is deleted, not parked. The
former Draft Overlay (local file, author-private, "never in Supabase") is
replaced by the **Live Overlay**: one `arxa_dial_overlays` row per
design (patches jsonb text+attrs+provenance, rev stale-guard), written
ONLY through the author-token/service-role-validated `save_overlay`
RPC, read by EVERY dial (clients watch the author work in real time —
decision 5 of 2026-08-23 overturned), streamed over the existing rails
(local SSE `overlay` frame; static postgres_changes channel).
Undo/redo is a session-local inverse stack (~50, no server journal).
Revert-to-published empties the row and everyone snaps back. Source is
touched ONLY by the **eject bake**: the next eject fetches the overlay,
applies each patch through `patchMain` (the design-patch machinery),
and clears the row on full success (refused patches stay live — the
Orphaned-Pin doctrine for edits). Editing requires the Supabase store; a
memory-store design shows no Edit verb. Guests keep exactly two powers:
comment and pick themes.

### Live-verification amendments (deployed v12, 2026-09-11)

The redesign shipped and both probes (`tool/lens_edit_local.dart`,
`tool/lens_edit_live.dart`) run ALL PASS against the deployed worker. Three
laws the grilling missed, found under the live probes:

1. **Both-vocabulary stamps.** The selection walk binds to the NEAREST
   `data-arxa-id` OR `data-el` — the live artifact stamps authored text
   carriers `data-el`-only under `data-arxa-id` composites, and an
   id-only walk resolved every click to a refused wrapper (the whole page
   was uneditable). A `data-el` hit carries the `el:` identity
   `bindingFor`/`targetsForKey` already speak.
2. **The media-container law.** Media swap surfaces are stamped wrappers
   carrying an `img`/`video`, not just stamped media elements (this
   artifact stamps none of those). `src`/`srcset`/`poster` resolve through
   ONE descent (`mediaOf`) in live apply, the chip, and per-instance
   scoping; a wrapper holding BOTH text and media shows the type hint AND
   Swap. The eject bake REFUSES media attrs on non-media hosts (baking
   `src` onto a wrapper would claim success and silently lose the swap) —
   refused patches stay live.
3. **Undo rides sessionStorage.** "Session-local" means the TAB: every
   text save triggers the animator-converge reload ~1.4s later, which
   erased the stack exactly when the author reached for undo. The stack
   persists across that reload; closing the tab still kills it.
4. **Published-palette custody (incident, 2026-09-11 22:17Z).** The
   `arxa_dial_axes` row is the AUTHOR'S LIVE VOICE: a palette publish on
   the design server (loopback author or guest share link, Q10) writes
   it, and the deployed site settles every fresh load onto it via
   palette.js's remote fetch — an open PUBLIC tab carried no channel
   (Q9; closed by law 5 below); a dial-credentialed tab
   repaints live over Realtime. NEVER "restore" the row from a
   remembered invariant: a 22:17Z restore to `c-2e1f27` clobbered a
   publish made four minutes earlier (the `c-1a1423` paste at 22:13Z,
   correctly baked by the 22:14Z eject), leaving the live page baking
   one palette while settling another. The eject bake reads the row at
   eject time — a bake and a row that DISAGREE mean someone published
   between eject and verify, not that the bake drifted. When they
   disagree, ask the author which pick stands before touching the row.
5. **The public palette ear (deployed v13, 2026-09-11 — researched).**
   The Q9 gap closed: a bare public tab — no dial, no credential — now
   HEARS published palette changes live instead of waiting for a
   reload. palette.js (static mode, baked `remote` config) subscribes
   ONE Supabase Realtime postgres_changes channel on
   `arxa_dial_axes` for this design. The laws, each researched in the
   2026-09-11 session: SAME-KEY (the publishable key already baked in
   the page; Realtime enforces RLS the way a normal query would — the
   anon role sees exactly the axes row it can already REST-read);
   LEAST-CHANNEL (axes only — never pins, replies, overlays);
   DIAL-YIELDS (a page carrying `document._arxaDial` stands down — the
   dial's Realtime covers the tab, no duplicate connection);
   VISIBILITY (the socket-pool law: hidden tab holds no connection;
   show resubscribes + one REST resync — missed frames never replay);
   VALIDATE-THEN-APPLY (frame ids ride the valid() regex + the
   dressable-manifest law, `?palette=` receipts are never stomped —
   ADDENDUM 18); DEGRADE (CHANNEL_ERROR/TIMED_OUT retries with capped
   backoff while visible, five strikes, then silence until the tab
   hides and shows again — the free plan's 200-connection Realtime cap
   degrades to boot-fetch freshness, never breakage). supabase-js
   lazy-loads from the already-shipped vendor asset, only in static
   mode, only while visible. Rejected alternative: worker-side
   SSE/Durable-Object fan-out — a second source of truth and new
   infra for a channel Supabase already owns. Verified live by
   `tool/lens_palette_public.dart` (9/9) plus the
   `tool/lens_live_guest.dart` regression (11/11).
6. **The contrast engine (deployed v14, 2026-09-11 — grilled, seven
   locked decisions).** Every sheet the plane ships renders its
   CONTRACTED PAIRS at WCAG 2.2 AA by construction: 4.5:1 body, 3:1
   large + non-text (SC 1.4.3/1.4.11); APCA ships as an advisory
   readout, never a gate. The contract lives in `_template.json`
   (`pairs` — token/keyed-rule co-locations the sheets really paint;
   `familyPairs` — the general expansion, used sparingly;
   `surfaces` — family→surface-token map; rule `key`s). The solver
   (`palette_contrast.dart`, the ONE home of the contrast math):
   per-slot, all-pairs-at-once — (1) nearest passing OKLCH lightness
   (hue + chroma preserved, scanning both directions, so the phase is
   polarity-agnostic); (2) POLARITY INVERSION — the Radix law: a
   mid-dark surface gets light text, because surfaces are the
   palette's character and bleaching them is the one move worse than
   flipping an ink (surface tokens and mapped surfaces never flip);
   (3) the surface moves only when genuinely stuck — least shift that
   satisfies every pair it carries. Pasted anchors and moodboard
   measured hexes stay VERBATIM in palettes.json; every solved value
   is a derived output logged in the sheet header (`contrast:`
   lines). MANIFEST carries `auto` per palette: AUTO solves at every
   render; a hand edit flips MANUAL (ships verbatim, readouts show
   red, the gate fails it); `POST /palettes/resolve` re-solves back
   to AUTO. The P5 gate judges the SHIPPED css — hexes read in render
   order, alpha slots composited — catching hand edits and derivation
   bugs alike; a template with no contract earns an advisory note
   (legacy planes stay green). The dial's Theme slide shows live
   per-pair readouts (WCAG ratio + APCA Lc) off the rendered page and
   every card wears its AUTO/MANUAL chip with a one-click Re-solve.
   `arxa design palette-index` preserves the contract across
   re-indexes (pairs/familyPairs/surfaces carried verbatim, rule keys
   matched by sel/at/tpl signature). Known residue, by design: the
   DEFAULT palette's contrast is the authored base corpus' own (it
   has no sheet to solve), and transient base-corpus states (hover,
   copied) ride outside the sheet contract. Verified: unit suite
   (11), `tool/lens_contrast.dart` DOM truth on the deployed worker
   (3.08/4.60/10.16 vs targets), palette-ear + guest regressions
   ALL PASS on v14, `arxa design lint` clean P1–P5.

## Addendum — cursor law v2 (2026-09-12): the animated orb, not the caret

**The correction.** The operator's cursor complaint was about the ANIMATED
cursor (dot + outlined orb, assets/app/cursor.js) — not the text caret the
previous addendum solved. It "used to be dynamic and change color but now no
more". Systematic-debugging reproduction (new tool/lens_cursor_probe.dart,
DOM truth: synthetic mousemove per section, state read from the live dot,
surface from the hit chain): the reference law — ACCENT everywhere except
the #hero-section Y-band → INK — flips nowhere else, and under the
published c-1a1423 the accent #372549 is 1.3:1 from the ink surface
#1a1423: the ring was INVISIBLE across clientstories/pricing/faq/footer
(dot 1.30, idle mix 1.13) and the two states were chromatic twins
(1.3 apart) — the coded flip existed but was imperceptible. The marine base
failed too (ocean ring idle 1.7 on paper) — the law's premise (bright
accent on a mostly-light page) died with the rebrand, not with the plane.

**Law v2 (motion 1:1, color superseded).** The state is picked PER SURFACE
from the palette's own poles, at every pointer update AND on scroll
(rAF-throttled — a still pointer over a scrolling page must not keep a
stale state):

- surface = nearest opaque background walked from the top-hit element;
- candidates in preference order [--accent, --ink, --paper, --white,
  #0a0d12] — accent FIRST, so a genuinely bright accent keeps the
  reference signature where it clears the floors;
- TIER 1 at reference paint (idle stroke alpha .5, stuck stroke alpha .55):
  legal = dot >= 3.0 AND idle-mix >= 2.0 AND stuck-mix >= 3.0. The idle
  floor is the one that matters — the free trail is what the eye follows
  95% of the time, and it is why washed accents lose to the poles;
- TIER 2 for mid-tone fields (--dark #10a22d, #8e518d class — no solid
  color clears 3.0 at .55): idle gate unchanged, stuck stroke paints more
  opaque [.65, .8, 1.0] until it clears; the chosen alpha rides
  data-arxa-stuck-alpha on the dot so the lens audits the real paint;
- mix math is ROUNDED to whole channels in the law — the audit must see
  exactly what the law sees or boundary palettes (c-293f14, idle 1.98 vs
  2.005) flap between legal and illegal.

Net effect: a visible pole flip at every light/dark section boundary — the
dynamic color change, now structural instead of assumed. The hero-band
special case and [data-cursor-dark] scanning are DELETED (dead: no markup
uses them; the surface walk subsumes both). The native [data-cursor-dot]
fallback image (pricing mailto cards sit on the DARK section) is now
dual-tone — white ring around the dark core, legible on both poles
(base.css).

**Audit law (tool/lens_cursor_probe.dart, permanent).** Per section:
dot >= 3.0 hard; stuck-mix at the REPORTED alpha >= 3.0 hard; idle-mix
>= 2.0 (washed guard; 2.0-2.99 prints SOFT); DYNAMISM — states over darkest
vs lightest surfaces must differ by >= 1.5; STALENESS — after scrolling
without moving, a 1px jiggle must not change the state. Hidden zones
([data-cursor-dot]/[data-cursor-hide]) are skipped. Verified: all six
palettes ALL CURSOR CHECKS PASS locally; suite 2035/2035; deployed
v18 755046ef-1734-46a3-b89b-5ebecd577ddb and probed LIVE green
(c-1a1423: dark sections flip to paper — dot 11.99 / idle 3.90 / stuck
4.43; dynamism 3.35). Contrast sweep re-run: only the two documented

## Addendum — cursor law v2.2 (2026-09-12, later still): the phantom pin

audit shared the identical blind spot. FIX (law v2.2): parseColor resolves
`color(srgb R G B [/ A])`; the probe's parse carries the same rule
(parity). Other color() spaces stay unparseable by design — both sides
agree on the rule, so the audit still sees what the law sees.

**Pixel ground truth (tool/lens_cursor_truth.dart, permanent).** The DOM
audits prove the law and its walker agree; only rendered pixels prove they
agree with REALITY. The truth probe runs the same grid, hides the cursor
layer at each point, screenshots, decodes the PNG, and takes the median of
5 sampled pixels (center + 4 at 24px) as the surface; the law's own belief
now rides `document.__arxaCursor` (the _arxaCaretPick precedent) so every
row shows law-vs-pixels. Classification per the locked contract: floors

content overlaps (glyph/vector art — the teams wordmarks, the zoom petal;
