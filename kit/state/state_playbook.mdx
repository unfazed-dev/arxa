### Usage & wiring

Add the package via a path dependency (`arxa_kit_state: path: ../state`) and import `package:arxa_kit_state/arxa_kit_state.dart`. There is no locator or `@StackedApp` registration step — `arxa_kit_state` is pure Dart with zero Flutter dependency, so a `ArxaKitStateNotifier` is constructed directly rather than resolved through `StackedLocator`. The minimal usage drives a notifier with `track` and observes `stream`:

```dart
final notifier = ArxaKitStateNotifier<Profile>();
await notifier.track(repository.loadProfile()); // loading → success/error
notifier.stream.listen((state) => /* rebuild */);
notifier.state;     // synchronous current value
```

### Architecture

The package is a single inward-facing vocabulary: a sealed `ArxaKitState<T>` (idle/pending/loading/success/error) with `when`/`map` combinators sits at the core, wrapped by `ArxaKitStateNotifier<T>`, which holds the current state and a broadcast `StreamController`. Two static collaborators govern behavior — `ArxaKitStateTransition` (a legal-transition matrix queried by an assertion inside `emit`) and `ArxaKitFailure` (the normalized error shape carried by `ArxaKitError`, where `ArxaKitFailure.from` absorbs any thrown object). Two ports are stubbed for later phases: `ArxaKitStatePersistence<T>` hydrates terminal state across launches (with `ArxaKitNoStatePersistence` as the no-op default), and `ArxaKitRetryPolicy` is a testable value object whose `track` integration is scheduled. Dependency direction points strictly inward to `dart:async` plus `meta` — no Flutter, no cross-kit imports.


### Gotchas

There is no platform setup — `arxa_kit_state` is pure Dart with no native channels, permissions, or manifest keys. The broadcast `stream` does not replay the current value on subscribe; read `state` synchronously to get it. `emit` no-ops when the next state compares equal (every case implements value equality), and a transition outside `ArxaKitStateTransition`'s matrix trips an assertion in debug only — it is still applied in release, so illegal sequences never crash production but will silently slip past in tests unless `guardTransitions` is left on. In tests, drain the broadcast queue with `await Future<void>.delayed(Duration.zero)` before asserting a recorded sequence, and always call `dispose()` to close the controller.


### Testing

`package:arxa_kit_state/arxa_kit_testing.dart` provides:

- **`ArxaKitStateRecorder<T>`** — subscribes to a notifier and records the emitted
  sequence for `expect(recorder.states, [...])` (leans on value equality).
- **`ArxaKitScriptedStateNotifier<T>`** — bypasses the guard so tests can push
  illegal or repeated sequences via `script` / `scriptAll`.

```dart
final notifier = ArxaKitStateNotifier<int>();
final recorder = ArxaKitStateRecorder<int>(notifier);
await notifier.track(Future.value(42));
await Future<void>.delayed(Duration.zero); // drain the broadcast queue
expect(recorder.states, const [ArxaKitIdle<int>(), ArxaKitLoading<int>(), ArxaKitSuccess<int>(42)]);
```

### Decisions / ADRs

The package is deliberately standalone: its only backing dependency is `meta` (for `@immutable`/`@protected`), with everything else drawn from `dart:async`. It exists to be the *intended* common async-state vocabulary that the other kits' ports converge on — but that unification is a documented later phase, so there are no cross-kit imports today and each kit still ships its own typed results. Choosing pure Dart (zero Flutter) keeps the vocabulary usable inside services and ViewModels without a Flutter binding, and makes the `ArxaKitStateRecorder` / `ArxaKitScriptedStateNotifier` tests in `arxa_kit_testing.dart` plain `package:test` suites. The transition guard is debug-asserted rather than runtime-enforced so release builds never crash on an unexpected sequence.
