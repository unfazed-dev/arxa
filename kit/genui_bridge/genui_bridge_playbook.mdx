### Overview & role

Provider- and model-agnostic reliability core for making any LLM emit valid A2UI v0.9 JSON messages for Flutter's genui package — an A2UI message model, incremental stream parser, catalog-schema validation, and a bounded repair loop over a thin AppBoxKitChatStream port (OpenAI-compatible and Anthropic adapters). Pure Dart, zero Flutter imports.

### Usage & wiring

```dart
import 'package:appbox_kit_genui_bridge/appbox_kit_genui_bridge.dart';

final chat = AppBoxKitOpenAIChatStream(
  model: 'qwen3:8b',
  baseUrl: Uri.parse('http://localhost:11434'), // no apiKey — local server
);

final bridge = AppBoxKitGenuiBridge(
  chat: chat,
  catalogId: 'appbox.dev:catalog',
  catalog: {
    'StageCard': {
      'type': 'object',
      'properties': {
        'id': {'type': 'string'},
        'component': {'const': 'StageCard'},
        'title': {'type': 'string'},
        'status': {'type': 'string', 'enum': ['pending', 'running', 'done']},
      },
      'required': ['id', 'component', 'title', 'status'],
    },
    // …one schema per catalog component type. Runtime input, flattened —
    // see the validator ceiling below.
  },
);

try {
  final turn = await bridge.generate([
    const AppBoxKitChatMessage.user('show me the build pipeline status'),
  ]);
  // Only valid messages ever get here. Forward the canonical JSONL to the
  // Flutter client, whose genui A2uiTransportAdapter.addChunk() consumes it:
  final jsonl = turn.toJsonl();
} on AppBoxKitGenuiBridgeFailure catch (f) {
  // Still invalid after 1 + maxRepairs attempts: f.errors, f.lastRawOutput.
}
```

What you get, in layers (each usable on its own):

- **`AppBoxKitA2uiMessage` model** — parse/serialize the four v0.9 verbs
  (`createSurface`, `updateComponents`, `updateDataModel`, `deleteSurface`).
  Read-tolerant of the rename-in-flight (`surfaceUpdate`/`dataModelUpdate`
  accepted as aliases), canonical v0.9 on write. Strict on
  `version == 'v0.9'`, because that is what genui's `a2ui_core` accepts.
- **`AppBoxKitA2uiStreamParser`** — `StreamTransformer<String, AppBoxKitA2uiStreamEvent>` that
  assembles messages split across arbitrary chunk boundaries (fenced blocks,
  balanced-brace objects, JSONL separators), passes prose through as
  `AppBoxKitA2uiTextEvent`, and surfaces malformed/truncated payloads as
  `AppBoxKitA2uiErrorEvent`s instead of throwing.
- **`AppBoxKitGenuiBridge`** — prompt → parse → catalog validation → bounded repair,
  per turn. An attempt that mixes valid and invalid messages is discarded
  whole; a turn's messages are only emitted once every one validates.
- **`lib/appbox_kit_testing.dart`** — `FakeAppBoxKitChatStream` (script queues + call recording)
  for testing your own bridge consumer without network.

### Architecture

Four layers, each usable on its own, all depending inward on the protocol
core — nothing depends on Flutter or another kit:

- **Protocol core** (`appbox_kit_a2ui_message.dart`) — the four-verb `AppBoxKitA2uiMessage`
  model. The single seam that absorbs A2UI renames: v0.8 verb aliases are
  accepted on read, canonical v0.9 is always written.
- **Stream layer** (`appbox_kit_a2ui_stream_parser.dart`) — `AppBoxKitA2uiStreamParser`, a
  `StreamTransformer<String, AppBoxKitA2uiStreamEvent>`. Errors flow as data
  (`AppBoxKitA2uiErrorEvent`), never as exceptions, so the repair loop can consume
  them without try/catch plumbing.
- **Port + adapters** (`appbox_kit_chat_stream.dart`, `appbox_kit_sse_transport.dart`,
  `adapters/`) — the one abstraction is `AppBoxKitChatStream`
  (`Stream<String> complete(messages, {schema})`). Adapters build the
  provider request and parse SSE; the actual HTTP is an injected
  `AppBoxKitSseTransport` function (default: dart:io `appBoxKitHttpPostStream`), which is how
  tests assert request shapes with zero network.
- **Orchestrator** (`appbox_kit_genui_bridge.dart`) — `AppBoxKitGenuiBridge.generate` runs one
  turn: prompt (catalog schemas embedded) → streamed parse → catalog
  validation → bounded repair (re-ask with the error appended, n ≤ 2) →
  `AppBoxKitA2uiTurn`, or a typed `AppBoxKitGenuiBridgeFailure`. An attempt that mixes valid
  and invalid messages is discarded whole — only fully valid batches leave
  the bridge.


### Gotchas

- **Pinned to A2UI v0.9** — the only version genui 0.10.1's `a2ui_core`
  accepts. Envelopes without `version: "v0.9"` are rejected, and v0.8's
  `beginRendering` is *not* aliased (its body shape differs from
  `createSurface`). A2UI is pre-1.0; when re-pinning, re-fetch the fixtures
  in `assets/a2ui/` and update `PROVENANCE.md`.
- **`AppBoxKitJsonSchemaValidator` is a subset validator** — `$ref`/`$defs`,
  `allOf`/`oneOf`/`anyOf`, `pattern` and `format` are ignored. Flatten refs
  and unions out of catalog schemas before handing them over (they are
  runtime inputs, not compiled in).
- **Batch semantics** — `generate` buffers each attempt; there is no
  progressive emission of a partial batch. Consumers forwarding to a genui
  client should send `AppBoxKitA2uiTurn.toJsonl()`.
- **Provider-native structured output is never load-bearing** — the
  `schema` hint maps to OpenAI `response_format` but is *ignored* by the
  Anthropic adapter (no shape-preserving native mode). Reliability comes
  from validate + repair, not from the hint.
- **`appBoxKitHttpPostStream` has no timeout or retry** — wrap the `AppBoxKitSseTransport`
  seam in the embedding daemon if it needs either. Auth is an injected
  header per request; nothing is stored.
- **Typed failure** — after `1 + maxRepairs` attempts, `generate` throws
  `AppBoxKitGenuiBridgeFailure` carrying `errors` and `lastRawOutput` for
  diagnostics; it is an exception, not a silent empty turn.

### Decisions / ADRs

- **Pure Dart, zero dependencies** — the primary consumer is appboxd, a
  dart:io daemon, so the package has no Flutter imports and no third-party
  deps at all. This keeps it inside the repo's standalone-topology default.
- **dart:io HTTP behind a `AppBoxKitSseTransport` typedef seam, not `package:http`** —
  no kit in the repo depends on `http`/`dio`, and the function seam makes
  both adapters unit-testable without mocking dart:io types.
- **Hand-rolled subset schema validator** — no kit depends on a JSON Schema
  package and the catalog's dataSchemas are caller-controlled runtime
  inputs, so the object/properties/required subset suffices (ceiling marked
  `# kimitail:` in `appbox_kit_json_schema.dart`; upgrade to a real schema package the
  day a catalog needs union types).
- **Rename tolerance in exactly one place** — the appbox plan pins the
  bridge against genui's experimental 0.x API "with one adapter seam for
  renames"; that seam is `AppBoxKitA2uiMessage.fromJson`'s alias map.
- **Unprefixed package name** — `appbox_kit_genui_bridge` (like `ui_library` and
  `branding`) is the name the appbox consolidation plan
  (`consolidate-one-app-plus-daemon.md`, "Kit candidate — kit_genui")
  assigns; the Flutter layer (`kit_genui`) is a future sibling kit.
- **Provenance fixtures** — `assets/a2ui/server_to_client.json` is a
  verbatim copy of the canonical v0.9 schema (fetched 2026-07-28); the
  spec↔code disagreements (verb renames, schema-strictness gap) are
  recorded in `assets/a2ui/PROVENANCE.md`.
