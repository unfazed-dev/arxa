### Usage & wiring

Add the package as a path dependency (`arxa_kit_core: path: ../core`), then `import 'package:arxa_kit_core/arxa_kit_core.dart';` for the whole public surface. The kit resolves services through `StackedLocator.instance` (`lib/kit_locator.dart`) — the same singleton your app's generated `locator` uses — so register `KitErrorService` and `KitThemeService` in your `@StackedApp` services list and existing `locator<T>()` call sites work unchanged. For theming, hand `kitLightTheme()` / `kitDarkTheme()` to `MaterialApp` (pass `accent` to override the brand primary), then drive mode changes through `locator<KitThemeService>()`. A minimal touch: `KitPlatform.isIOS`, `KitColors.accent`, or `KitTimeUtils.getPersonalizedGreeting(name)`.

### Architecture

The kit is a standalone leaf tier — it depends only on Flutter, `stacked`/`stacked_services`/`stacked_shared`, `rxdart`, `talker_flutter`, `flutter_animate`, and `shared_preferences`, with no dependency on a host app or sibling kit packages. Service resolution is decoupled through `lib/kit_locator.dart` (`final locator = StackedLocator.instance`), which keeps the kit portable across any Stacked app. Reactive services (`KitErrorService`, `KitThemeService`, `KitSelectableService`) mix in Stacked's `ListenableServiceMixin` and back their state with rxdart `BehaviorSubject`s, while `KitPlatform` is the single source of truth for host identity and native-chrome capability gating (pure Dart, web-safe). Design tokens (`KitColors`/`KitDarkColors`, `KitGlyphs`, the `k*` constants) are `abstract final` classes and `const` values; `kitLightTheme`/`kitDarkTheme` compile them into `ThemeData`, and `KitThemeService` deliberately holds no color values — it only flips mode and persists the key.


### Gotchas

`KitPlatform.iosMajor` parses `Platform.operatingSystemVersion` with a regex — sync and dependency-free, but fragile to Apple reformatting the string; the noted upgrade path is `device_info_plus.systemVersion` if it ever mis-parses in the field. Every `dart:io` `Platform` read is guarded by `kIsWeb`, so the kit is web-safe, but the vendored `cupertino_native_better` (a path-dep fork of upstream 1.5.2 carrying a local iOS tab-bar fix) and the `m3e_collection` Android tier only render real native chrome on their respective platforms. The warm-neutral palette intentionally contains no pure black or white — primary text is a warm brown (light) / cream (dark) — so don't swap in stark `#000`/`#FFF` expecting it to tonally match. `KitThemeService` persists its mode via `shared_preferences`, so that plugin's platform setup must succeed for the choice to survive a restart.


### Testing

Run this package's tests with `flutter test` (not `dart test`): the suite imports `flutter_test` and widget-bound services, so the plain Dart test runner cannot load it. From the repo root: `cd kit/core && flutter test`.

Inject deterministic identity with `KitPlatformOverride({isIOS, isAndroid, iosMajor, targetPlatform})` in `setUp` and clear it with `KitPlatform.reset()` in `tearDown` — the only way to exercise the native-chrome gating branches without a real device. The reactive services are Stacked `ListenableServiceMixin`s backed by rxdart `BehaviorSubject`s, so register a fake through `locator` (or seed the real service) and await emissions from `KitErrorService.unreadCount$` / `widgetEventCounts$` / `loadingWidgets$` to assert call counts and state. `KitSelectableService` exposes a synchronous `selectedIDs` getter (plus the `selectedIDs$` stream) for direct selection assertions, and `KitTimeUtils.getPersonalizedGreeting` takes an optional `DateTime` so greeting logic is fully deterministic. The package ships only `flutter_test` (no dedicated recording double), so assertions lean on the exposed streams and getters above.

### Decisions / ADRs

The kit deliberately reuses `StackedLocator.instance` rather than declaring its own locator, so it stays decoupled from any host's generated `app.locator.dart` and portable across Stacked apps — the same singleton the host already registers through. It is a standalone leaf with no host or sibling-kit dependency, chosen so the design tokens, platform gate, and reactive services can be reused without dragging an app graph along. `KitPlatform` collapses the Liquid Glass (iOS ≥ 26) and Compose M3 / M3-Expressive (any Android) capability checks into one `supportsNativeChrome` gate, mirroring the validated "starling" `supportsNative` pattern so the tier choice lives in a single testable place. On the dependency side, `cupertino_native_better` is vendored as a path dep (local fix survives `pub cache repair`) and `m3e_collection` is taken as the publisher's umbrella bundle rather than per-widget cherry-picks, since the kit wires most of its components.
