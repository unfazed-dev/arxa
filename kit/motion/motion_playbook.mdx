### Overview & role

Deterministic entrance/exit choreography for Stacked apps. `ArxaKitMotionScope` establishes one 0→1 driver per subtree — the enclosing route's animation by default (push wakes, pop/swipe-back scrubs down), or any explicit `Animation<double>` (a `ArxaKitDirectionalTabTransition`-style tab animation, a scroll-mapped animation, or a manual `AnimationController` replay). Descendant `ArxaKitWake` widgets each claim a stagger slot and slice their window from that single timeline using pure `FadeTransition`/`SlideTransition`/`ScaleTransition` composition — cheap, reversible, no ticker owned. Standalone capability kit; no dependency on arxa_kit core.

### Usage & wiring

```dart
import 'package:arxa_kit_motion/arxa_kit_motion.dart';

// 1. Route-driven (default): children wake on push, scrub down on pop.
ArxaKitMotionScope(
  child: Column(children: [header, body, footer].wakeAll()),
);

// 2. Single widget, explicit slot + spec preset:
Text('hi').wake(order: 3, spec: ArxaKitMotionSpec.energetic);

// 3. Any flutter_animate effect on the same timeline:
card.animate(adapter: ArxaKitMotionAdapter.of(context)).fadeIn().blurXY(begin: 8, end: 0);

// 4. Manual replay: pass your own driver; forward(from: 0) re-wakes.
ArxaKitMotionScope(driver: _controller, child: demo);
```

Tune via the `ArxaKitMotionSpec` theme extension (or per-scope/per-wake `spec:` override): `staggerFraction`, `maxStartFraction`, `curve`, `offset`, `fade`, `scale`, `enabled` — presets `standard` / `subtle` / `energetic`.

### Architecture

`arxa_kit_motion` never imports `arxa_kit`. The allowed direction is the
reverse: `arxa_kit` core (or any app) may take a path dependency on this kit.
One driver per scope; `ArxaKitWake` slots are auto-claimed in build order (sticky
across rebuilds) or pinned via `order:` / `.wakeAll()` for lazy/sliver parents.


### Gotchas

`ArxaKitWake` degrades to rendering its child untouched when any of these hold: no `ArxaKitMotionScope` above it, `MediaQuery.disableAnimations` (reduce-motion) set, or the resolved `ArxaKitMotionSpec.enabled` false — shared components stay safe to embed anywhere, but it also means a missing scope fails *silently* (no wake, no error). Auto-claimed slot order follows build order, which lazy lists and slivers can shuffle — use explicit `order:` or `.wakeAll()` there. `ArxaKitMotionAdapter.of(context)` needs a `Builder` (or any descendant context) *inside* the scope, and each `.animate()` call consumes one stagger slot just like a `ArxaKitWake`. The only backing package is `flutter_animate` (^4.5.2), which must stay version-aligned with the showcase app and core.

### Decisions / ADRs

arxa_kit_motion is a standalone capability kit extracted alongside the phase 2B kits: choreography can be consumed without dragging in core's UI/navigation surface. It deliberately owns **no ticker** — every wake is a slice of one external 0→1 driver, which makes the whole choreography reversible for free (pop and interactive swipe-back scrub the entrance back down symmetrically). Pure Flutter transition widgets were chosen over flutter_animate for the core path (cheap, const-friendly, reversible), with flutter_animate integrated *at the edge* via `ArxaKitMotionAdapter` so its effect catalogue rides the same timeline instead of competing with it. Specs are a `ThemeExtension` so apps theme motion like color. The hard rule is that `arxa_kit_motion` never imports `arxa_kit`; the dependency direction is strictly reversed.
