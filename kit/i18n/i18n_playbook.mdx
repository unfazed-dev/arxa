### Overview & role

Locale machinery for arxa_kit apps — a ArxaKitLanguage value type, a persisted system+override locale model (ArxaKitI18n extends ChangeNotifier for live switching), intl-backed date/number/currency formatting, placeholder-parity checking, and an LLM locale directive for generative UI. Standalone capability kit; no dependency on arxa_kit core. Translation strings are deliberately NOT codegen'd here — apps own their gen-l10n output.

### Usage & wiring

Register in the locator at startup and wire `MaterialApp`:

```dart
// main.dart — create once, load the persisted override before runApp.
final store = await SharedPreferencesArxaKitLocaleStore.create();
final i18n = ArxaKitI18n(
  store: store,
  systemLocale: WidgetsBinding.instance.platformDispatcher.locale,
);
await i18n.load();
locator.registerSingleton<ArxaKitI18n>(i18n);

// MaterialApp — listen so the app rebuilds live on setLocale().
MaterialApp(
  locale: i18n.locale,
  supportedLocales: const [Locale('en'), Locale('pl')],
  localizationsDelegates: const [
    AppLocalizations.delegate, // from the APP's gen-l10n output
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
    GlobalCupertinoLocalizations.delegate,
  ],
  // ...
);

// A settings toggle — persists + notifies:
await i18n.setLocale('pl');   // live switch, persisted
await i18n.clearOverride();   // back to the system locale
```

Formatting in the effective locale:

```dart
i18n.formatDate(DateTime.now());          // "30 lip 2026" under pl
i18n.formatNumber(1234.5);                // "1 234,5" under pl
i18n.formatCurrency(1234.5, 'PLN');       // "1234,50 zł" under pl
```

Translation review guard:

```dart
i18n.placeholderParity(
  'You have {COUNT} new messages, {name}',
  'Masz {COUNT} nowych wiadomości, {name}',
); // true — same token set (case-sensitive)
```

LLM locale directive (generative UI / chat surfaces):

```dart
i18n.doNotTranslate = ['Acme', 'ProPlan'];
final systemPrompt = '${i18n.llmLocaleDirective()}\n\n$restOfPrompt';
```

### Architecture

Three small pieces, one dependency direction (service → port → plugin):

- `ArxaKitLanguage` — a pure value type: BCP-47 `tag` plus English/native display
  names. The static `ArxaKitLanguage.supported` table ships `en` + `pl`;
  `byTag` falls back to the base subtag (`'pl-PL'` → `'pl'`).
- `ArxaKitLocaleStore` — the persistence port (`read`/`write`/`clear` of a single
  override tag). `SharedPreferencesArxaKitLocaleStore` is the shipped adapter,
  over a `SharedPreferencesWithCache` scoped to the `'locale'` key.
- `ArxaKitI18n` — the service the app holds. It resolves the effective locale
  (persisted override → system locale → English), extends `ChangeNotifier`
  so `MaterialApp` rebuilds live on `setLocale`/`clearOverride`, and formats
  dates/numbers/currencies through `intl` in the effective locale. It also
  owns the translation-review guard (`placeholderParity`) and the
  `llmLocaleDirective` prompt block for generative UI.

The kit never sees translation strings: ARB files and gen-l10n
`AppLocalizations` live in the app, which also owns the wiring
(`MaterialApp.locale`, delegates, supported locales). No kit depends on
`arxa_kit_core` or `stacked` — the app registers `ArxaKitI18n` in its own
locator.


### Gotchas

- **`intl: any` is never pinned** — its version is SDK-pinned through
  `flutter_localizations`. Adding a version constraint will conflict.
- **The model is system + override + live-switch.** `locale`/`bcp47` resolve
  override → system locale → English. `setLocale` persists *and* notifies, so
  wire `MaterialApp` to listen rather than restarting the app.
- **Translation strings live in the app.** The kit has no ARB/codegen; it
  expects the app's gen-l10n delegates to sit next to the
  `flutter_localizations` delegates.
- **`SharedPreferencesArxaKitLocaleStore.create()` is async** — create it once
  before `runApp`, not per viewmodel.
- **The LLM directive is a prompt block, not a translator** — it steers the
  model to answer in `languageNameEn`/`languageNameNative`, preserve
  `{placeholder}` tokens, and emit ISO 8601 / plain numbers so the app keeps
  formatting authority. `doNotTranslate` injects brand/product terms.

### Decisions / ADRs

- **Standalone (no kit edges).** Follows the star-topology default:
  persistence sits behind the `ArxaKitLocaleStore` port and the app binds it —
  the kit never imports `arxa_kit_core` or `stacked`.
- **No codegen in the kit.** Translation strings are app content, not kit
  machinery: ARB files and gen-l10n output stay in the app, keeping the kit
  generic over any locale set. The kit supplies resolution, persistence,
  formatting, and guards — nothing that needs regenerating per app.
- **`intl: any`, never pinned.** The version is SDK-pinned through
  `flutter_localizations`; pinning it in the kit would conflict at
  `pub get`.
- **English default + Polish at launch, generic table.** `ArxaKitLanguage.supported`
  ships `en` + `pl` because those are the launch locales; lookup is
  tag-based with base-subtag fallback, so adding a locale is a table entry
  plus the app's ARB file — no kit change.
