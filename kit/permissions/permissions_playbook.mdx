### Overview & role

### Usage & wiring

Add `appbox_kit_permissions` to your app's `pubspec.yaml`. The kit is standalone — it has no Stacked framework deps and ships no `@StackedApp` wiring (see the integration map) — so registration is a plain locator bind of `PermissionHandlerKitPermissionsService()` against the `KitPermissionsService` interface, resolved through the host app's locator (`StackedLocator.instance`). Inject the port and branch on the four-state status, escorting to system Settings when the OS will never prompt again: `final s = await service.request(KitPermission.camera); if (s.requiresSettingsEscort) { await service.openAppSettings(); }`. No README Usage/Setup section exists yet; the snippet above uses only the port methods documented under *Scope*.

### Architecture

Classic ports-and-adapters. `KitPermissionsService` is the abstract interface the app depends on; `PermissionHandlerKitPermissionsService` is the sole production adapter, mapping `KitPermission` onto `permission_handler`'s `Permission` and projecting the plugin's richer `PermissionStatus` onto the four-state `KitPermissionStatus`. The adapter holds no state of its own — every call is a live OS query, and iOS `limited`/`provisional` collapse to `granted` (usable access). Dependency direction runs one way — app → port → adapter → `permission_handler` → platform — and the package imports no other kit (not `appbox_kit`, `stacked`, or `stacked_services`), so it can sit at the bottom of the kit graph as the root permissions kit the hardware kits will eventually consume.


### Gotchas

`permission_handler` is a thin wrapper over the platform authorization APIs
(iOS `AVCaptureDevice`/`CLLocationManager`/`PHPhotoLibrary`/… and Android
runtime permissions). No custom native code ships in this package.


### Testing

### Decisions / ADRs

Per `kit_matrix.md` §2 (*standalone by default*) and §6 (*native-first phasing*), `appbox_kit_permissions` is a plugin-neutral port with `deps_kit: []` — chosen so the hardware kits can eventually route authorization through one typed seam instead of each taking a direct `permission_handler` dependency. The backing plugin is `permission_handler` ^12.0.3 (verified on pub.dev 2026-07-14), picked because it is a thin, well-maintained wrapper over iOS `AVCaptureDevice`/`CLLocationManager`/`PHPhotoLibrary` and Android runtime permissions, which lets the kit stay native-first with no custom native code of its own. The four-state status — with iOS `limited`/`provisional` collapsed to `granted` — and the `requiresSettingsEscort` contract are the deliberate surface: UIs branch on actionable states and stop re-prompting once the OS will never show another dialog. No path dependency is registered from this kit yet; the "root kit others consume" topology is deferred to the downstream workspace-reconciliation pass (see README *Non-goals*).
