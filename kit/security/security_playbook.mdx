### Usage & wiring

Add `arxa_kit_security` to your app's `pubspec.yaml` and import `package:arxa_kit_security/arxa_kit_security.dart`; for tests, import `package:arxa_kit_security/arxa_kit_testing.dart` to pick up the scriptable fakes (`FakeArxaKitBiometricService`, `FakeArxaKitSecureStorageService`, `FakeArxaKitCryptoService`, `FakeArxaKitPinVerifier`, `FakeArxaKitDeviceIntegrityService`). The kit depends on no other kit, so at bootstrap the host app registers each production binding in its locator — `ArxaKitBiometricService` → `LocalAuthArxaKitBiometricService`, `ArxaKitSecureStorageService` → `FlutterSecureStorageArxaKitSecureStorageService`, `ArxaKitCryptoService` → `CryptographyArxaKitCryptoService` (full block in Architecture). After wiring, consume the ports directly: `biometricService.authenticate()` returns a typed `ArxaKitBiometricResult`, `secureStorage.write(key: k, value: v)` persists through the iOS Keychain / Android EncryptedSharedPreferences, and `cryptoService.encryptBytes(...)` yields an AES-GCM-256 `ArxaKitSecretBox` whose tag is verified on `decryptBytes`.

### Architecture

This package depends on no other kit. The host app (or `arxa_kit` core)
binds the ports in its locator:

```dart
// app bootstrap — choose the production bindings you need
locator.registerSingleton<ArxaKitBiometricService>(LocalAuthArxaKitBiometricService());
locator.registerSingleton<ArxaKitSecureStorageService>(
  FlutterSecureStorageArxaKitSecureStorageService(),
);
locator.registerSingleton<ArxaKitCryptoService>(CryptographyArxaKitCryptoService());
```


### Gotchas

- **AES-GCM nonce handling.** `encryptBytes` draws a fresh random 12-byte
  nonce per call unless one is passed in. Never reuse a nonce with the same
  key — a fresh nonce per encryption is the requirement this default
  satisfies. If you supply an explicit nonce, you own uniqueness.
- **PIN storage is HMAC, not a slow KDF.** `SecureStoragePinVerifier` stores a
  per-PIN salted `HMAC-SHA256`. HMAC-SHA256 is fast, so this is **not**
  brute-force-resistant: an attacker who exfiltrates the secure-storage
  contents can grind a short numeric PIN offline. This is the documented
  portable default, acceptable when the app enforces attempt limits — which
  `ArxaKitAppLockController` does (biometric lockout + PIN cooldown). For a
  high-value lock, back the PIN with a rate-limited secure element
  (StrongBox / Secure Enclave) or a slow KDF (Argon2/ PBKDF2) by supplying
  your own `ArxaKitPinVerifier`.
- **Biometric-only.** `LocalAuthArxaKitBiometricService` passes `biometricOnly:
  true`; the device passcode fallback is the app-lock's job, not the
  biometric seam's.
- **Device integrity is phase 2.** No production binding ships; the stub
  throws. A real check must be native-first (no root-detection plugin
  dependency is added by this kit).

### Decisions / ADRs

- **Standalone by design.** The kit declares no dependency on `arxa_kit`, `stacked`, or `stacked_services`, so it ships as a pure capability layer; the host app owns locator registration and never inherits a framework coupling it does not need.
- **Typed ports over plugin types.** Each of the five seams is consumed through an abstract interface with plugin-neutral value types and results (`ArxaKitBiometricResult`, `ArxaKitCryptoFailure`, `ArxaKitIntegrityReport`). Backing-plugin types — `local_auth`'s `BiometricType` and `LocalAuthExceptionCode`, the `cryptography` package's `SecretKey` / `SecretBox` / `Mac` — are mapped at the boundary and never leak past it.
- **Backing packages (verified pub.dev 2026-07-14).** `local_auth ^3.0.2` (publisher `flutter.dev`) and `flutter_secure_storage ^10.3.1` cover platform Keychain/Keystore; `cryptography ^2.9.0` was chosen because its pure-Dart `DartCryptography` fallback runs fully off-device in `flutter test`, so the AES-GCM/SHA-256/HMAC backend is exercisable without a device.
- **Integrity deferred to a native-first phase.** Device integrity ships only the throwing `UnimplementedArxaKitDeviceIntegrityService` stub today; a real check is deferred so the kit takes no root-detection plugin dependency now, and the scriptable `FakeArxaKitDeviceIntegrityService` drives UIs and tests meanwhile.
