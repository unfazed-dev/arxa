### Overview & role

Stacked form management for arxa_kit apps — typed field/form controllers (pristine/dirty/validating/valid/invalid) with sync + async validation, a composable validator library, and code-first error mapping for i18n. Integrates with Stacked's form generator conventions.

### Usage & wiring

Add `arxa_kit_forms` to the consuming app's `pubspec.yaml`, then import the barrel. There is no service-locator or `@StackedApp` registration step: the kit ships only controllers and validators (no services), so it has nothing to register with the locator — you instantiate the controllers directly where the ViewModel needs them.

```dart
import 'package:arxa_kit_forms/arxa_kit_forms.dart';

final email = ArxaKitFieldController<String>(
  name: 'email',
  validators: [ArxaKitValidators.required(), ArxaKitValidators.email()],
);
final password = ArxaKitFieldController<String>(
  name: 'password',
  validators: [ArxaKitValidators.required(), ArxaKitValidators.minLength(8)],
);

final form = ArxaKitFormController([email, password]);
// form.canSubmit gates the submit button; form.values / form.errors are live maps.
await form.submit((values) => api.signIn(values));
```

To drive a generated Stacked form's `<field>ValidationMessage` getters from the same typed layer, mix `ArxaKitFormViewModelMixin` into a `FormViewModel` and call `syncArxaKitForm()` on change (see Architecture). For a plain `@FormTextField(validator:)`, adapt a composed validator down to the generator's signature with `.toStacked()`.

#### Wiring a field to a `ArxaKitNativeTextField` (app-side bridge)

`ArxaKitFieldController<String>` is value-based and validates on write; `ArxaKitNativeTextField` (in `ui_library`) is controller-based. The kit's star topology forbids `arxa_kit_forms` from importing `ui_library` — there is no kit→kit edge — so that bridge **cannot ship in-kit**. Each app owns a ~40-line **leaf adapter** widget: a `StatefulWidget` that manages only a `TextEditingController`'s create / dispose / sync. The source of truth (the `ArxaKitFieldController`, its value, validation, and `ArxaKitFieldStatus`) stays in the viewmodel — the adapter is plumbing, not state-splitting, mirroring stacked's own generated `$View` form mixin (stateful for controller disposal, not to hold state).

Sync is echo-free in both directions:

- **User typing** → `onChanged` → `field.value =` (drives validation + `StackedView` rebuild).
- **External prefill** (e.g. a model loaded into the VM) → `field.value =` → a `field` listener seeds the controller **only when the value differs** (`value != controller.text`); that equal-value guard avoids cursor resets on the echo of a user's own keystroke.

Reference implementation (upstream app): `lib/ui/widgets/kit_field_text_field.dart` — `KitFieldTextField`, a `StatefulWidget` wiring `ArxaKitFieldController<String>` → `ArxaKitNativeTextField`.

### Architecture

The kit is layered strictly by dependency direction, bottoming out at pure Dart plus `stacked`'s `FormViewModel` / `FormStateHelper` conventions. The error model — `ArxaKitValidationCode`, `ArxaKitFieldError`, `ArxaKitErrorMessages` — underpins the `ArxaKitValidator` / `ArxaKitAsyncValidator` / `ArxaKitStringValidator` typedefs and the `ArxaKitValidators` factory library (`required`, `email`, `minLength`, `maxLength`, `pattern`, `match`, `custom`, `compose`). On top of that, `ArxaKitFieldController<T>` wraps a single value with a `ArxaKitFieldStatus` (pristine / dirty / validating / valid / invalid), running sync validators first and async validators only on sync success, with concurrent `validate()` calls epoch-guarded; `ArxaKitFormController` then aggregates fields into a derived `ArxaKitFormStatus`, gates `canSubmit` on all-valid, and owns/disposes its fields by default.

The only file that touches Stacked's runtime surface is `ArxaKitFormViewModelMixin` — a thin edge adapter that pushes the kit's values and errors into `FormStateHelper.formValueMap` / `fieldsValidationMessages` so generated forms stay in sync. Everything below that edge has no Stacked dependency beyond the type conventions. `ArxaKitMultiStepFormController` (flows) and `ArxaKitFormDraftStore` / `ArxaKitInMemoryDraftStore` (persistence) are exported stubs that define the ports ahead of their durable implementations.

**Forms ↔ data are deliberately disjoint reactivity axes.** This kit is `ChangeNotifier`-based: `ArxaKitFieldController`/`ArxaKitFormController` (and `ArxaKitMultiStepFormController`) all `extend ChangeNotifier`, so a field's value/status change notifies the `StackedView` to rebuild, and the kit depends on `stacked` alone — **no `rxdart`**. `arxa_kit_data` is the opposite: `rxdart`-based. `KitSeedStore` and each auth backend own `BehaviorSubject`s, and `KitDataFacade` composes them with `Rx.combineLatest` / `.map` / `.debounceTime`, feeding `KitStreamBuilder` in the view. These two axes meet only in the viewmodel — field-state reactivity (`ChangeNotifier` → `StackedView` rebuild) on one side, data-stream reactivity (`rxdart` → `KitStreamBuilder`) on the other. The kit_matrix calls this out explicitly (§4): `arxa_kit_forms` is **not** a dependency of `arxa_kit_data` — "bind them in viewmodels". So don't go looking for an `rxdart` form-fields path; there isn't one, by design.


### Gotchas

No platform setup is required — the kit is pure Dart with no method channels, native permissions, or manifest keys. `ArxaKitFormController` owns and disposes its fields by default, so pass `ownsFields: false` if you inject field instances that outlive the form. Input formatters (email / OTP / mobile) still live in `arxa_kit` core and are intentionally not re-exported here; import them from core rather than waiting on this barrel. Finally, `ArxaKitMultiStepFormController` and durable draft storage are stubs today — only the `ArxaKitFormDraftStore` port and `ArxaKitInMemoryDraftStore` exist — so don't rely on durable draft-restore or branching/progress/back-stack wizard behavior yet.

### Decisions / ADRs

The kit depends on exactly one package — `stacked` (^3.5.0) — and deliberately not `stacked_services`, because the generator bridge needs only `FormViewModel` / `FormStateHelper` conventions and `stacked_services` would be dead weight. Errors are code-first: `ArxaKitValidationCode` is the primary i18n key, with a resolved English `ArxaKitFieldError.message` fallback, so apps can localize without forking validators or rewiring factories. Validator factories return typed `ArxaKitValidator<T>` rather than the generator's `String? Function(String?)` in order to preserve async and cross-field cases; `ArxaKitValidatorStackedAdapter.toStacked()` adapts down to the generator's signature only at the edge. Input formatters were left in `arxa_kit` core (a scheduled Phase 5 ride-along) rather than moved, to keep core untouched and the migration breaking-change-free.
