### Usage & wiring

Add `appbox_kit_documents` to your `pubspec.yaml` — it transitively pulls only `file_selector` and imports no other kit. Import `package:appbox_kit_documents/appbox_kit_documents.dart` to get every port plus its plugin-neutral value types. The production adapter is a `const` constructor with no dependencies, so you can hold it directly or register it into any service locator (e.g. the shared Stacked locator):

```dart
import 'package:appbox_kit_documents/appbox_kit_documents.dart';

final picker = FileSelectorAppBoxKitDocumentPickerService();
final AppBoxKitPickedDocument? doc = await picker.pickDocument(extensions: ['pdf']);
if (doc != null) {
  final Uint8List bytes = await doc.readBytes();
}
```

Note: the README does not yet carry an explicit Setup/registration block — only the working picker path above is sourced. Wire the scan/OCR/PDF ports only when you adopt their phase-2 native backends, since their shipped `Unimplemented…` adapters throw.

### Architecture

The kit is four `abstract interface class` ports — `AppBoxKitDocumentPickerService`, `AppBoxKitDocumentScanService`, `AppBoxKitOcrService`, `AppBoxKitPdfService` — each with its own concrete adapter behind the seam. Only the picker has a live adapter (`FileSelectorAppBoxKitDocumentPickerService` over `file_selector`); scan, OCR, and PDF ship `Unimplemented…` classes whose methods throw `UnimplementedError`, holding final signatures stable until the phase-2 native backends. Dependency direction is strictly outward: the package imports only `dart:typed_data` and `file_selector`, and nothing from `appbox_kit*`, `stacked`, or `stacked_services`. The `file_selector` `XFile` never crosses the seam — adapters project it onto plugin-neutral value types (`AppBoxKitPickedDocument`, `AppBoxKitScannedPage`, `AppBoxKitOcrResult`, `AppBoxKitPdfPageImage`), and bytes are read lazily so large files stay unloaded until used.

### Testing

`FakeAppBoxKitDocumentPickerService`, `FakeAppBoxKitDocumentScanService`,
`FakeAppBoxKitOcrService`, `FakeAppBoxKitPdfService`. Each supports a `failWith` error to

**user cancel**.

### Decisions / ADRs

The kit is **API-first by design**: it ships the full typed port surface now so app code compiles against final signatures, then backfills native adapters in phase 2 — which is why scan/OCR/PDF exist as throwing `Unimplemented…` stubs rather than being absent entirely. It is **deliberately standalone**: it takes no path dependency on `appbox_kit`, `stacked`, `stacked_services`, or `appbox_kit_permissions`, staying pure ports over native plugins and reusable outside the Stacked graph. The one working path uses `file_selector` (`^1.1.0`, verified pub.dev 2026-07-14) because it wraps the OS document pickers (`UIDocumentPickerViewController` on iOS, the Storage Access Framework on Android) without dragging in a heavier media dependency. The native-first plan pins each stub to a first-party engine — VisionKit/Vision/PDFKit on iOS, ML Kit/PdfRenderer on Android — and per the README's Non-goals, camera/photo-library permission for scanning is deferred to a downstream reconciliation pass rather than forcing a `appbox_kit_permissions` dependency now.
