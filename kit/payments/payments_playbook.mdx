### Overview & role

Native-first payments for arxa_kit apps — Apple Pay + Google Pay via Google's first-party pay plugin, behind a pluggable provider port so Stripe/PayPal backends slot in later. Typed ArxaKitPaymentResult, scriptable fakes.

### Usage & wiring

```dart
import 'package:arxa_kit_payments/arxa_kit_payments.dart';

final payments = DefaultArxaKitPaymentsService.native(
  applePay: const ArxaKitApplePayConfig.fromAsset('assets/apple_pay_config.json'),
  googlePay: const ArxaKitGooglePayConfig.fromAsset('assets/google_pay_config.json'),
);

if (await payments.canPay(ArxaKitPaymentMethod.applePay)) {
  final result = await payments.requestPayment(
    config: const ArxaKitApplePayConfig.fromAsset('assets/apple_pay_config.json'),
    items: const [ArxaKitPaymentItem(label: 'Total', amount: '99.99')],
  );
  switch (result) {
    case ArxaKitPaymentSuccess(:final token):   // forward token to your server / PSP
    case ArxaKitPaymentCancelled():             // user dismissed — do nothing
    case ArxaKitPaymentDeclined(:final reason): // retry with another method
    case ArxaKitPaymentError(:final message):   // log; not user-fixable
  }
}
```

Or drop in the button directly:

```dart
ArxaKitPayButton(
  applePay: const ArxaKitApplePayConfig.fromAsset('assets/apple_pay_config.json'),
  googlePay: const ArxaKitGooglePayConfig.fromAsset('assets/google_pay_config.json'),
  items: const [ArxaKitPaymentItem(label: 'Total', amount: '99.99')],
  onResult: (result) { /* same switch as above */ },
);
```

### Architecture

Hosts depend only on the `ArxaKitPaymentsService` port (`canPay` + `requestPayment`) and the sealed `ArxaKitPaymentResult`; `DefaultArxaKitPaymentsService` routes each call through a `ArxaKitPaymentsProviderRegistry` to the first registered `ArxaKitPaymentsProvider` whose `supportedMethods` contains the requested wallet. `ArxaKitPayPaymentsProvider` is the sole live adapter, wrapping the `pay` plugin, while `ArxaKitStripePaymentsProvider` and `ArxaKitPayPalPaymentsProvider` ship as same-shaped stubs that throw `UnimplementedError` until their phase arrives. Dependency direction is strictly models/service → providers → `pay`: the service and ViewModels carry no provider SDK, so backends can be swapped without touching call sites. The package is also standalone — it declares no dependency on `arxa_kit`, `stacked`, or `stacked_services`.


### Gotchas

Native setup is yours to own: Apple Pay requires the Apple Merchant ID entitlement and a matching `merchantIdentifier` in the profile JSON, and Google Pay requires merchant approval in the Google Pay & Wallet Console plus the gateway wiring in the Android manifest — this package ships the flow, not the merchant onboarding. The sample profiles under `example/` (`apple_pay_config.json`, `google_pay_config.json`) must be copied into the host app's own `assets/` and declared in its pubspec; no payment profile is bundled here. Note that Apple/Google Pay do not distinguish a card decline client-side, so a declined instrument surfaces as `ArxaKitPaymentError`, not `ArxaKitPaymentDeclined` — the decline-vs-error split only becomes meaningful once the Stripe/PayPal stubs (currently `UnimplementedError`) are implemented. This package only mints a wallet token; capturing/charging it is your server's job (an explicit non-goal), and it targets Android + iOS only — the `pay` plugin supports no other platform.

### Decisions / ADRs

The package backs itself with Google's first-party `pay` plugin because it wraps PassKit and the Google Pay API directly, driving the wallet the user already trusts without putting a third-party PSP SDK in the hot path. It ships standalone (no dependency on `arxa_kit`, `stacked`, or `stacked_services`) so the payments surface stays usable from non-stacked apps and is not coupled to the framework's release cadence — `pay ^3.3.0` is its only backing dependency. Stripe and PayPal were left as same-shaped stubs behind the `ArxaKitPaymentsProvider` port rather than baked in, so a real PSP backend can be added later without changing any call site: native-wallet coverage first, PSP capture deferred to the layer that actually owns it (your server).
