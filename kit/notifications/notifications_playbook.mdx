### Overview & role

Device-notifications port for arxa_kit apps — permission seam (typed result), push token / foreground-message streams, local notifications and per-notification badge, with a native-first flutter_local_notifications default. Distinct from arxa_kit core's in-app ArxaKitNotificationService (transient toast/snackbar).

### Usage & wiring

- **iOS/macOS:** notification capability + (for push) APNs entitlement and the
  `AppDelegate` registration are the app's responsibility.
- **Android:** the `POST_NOTIFICATIONS` runtime permission (API 33+),
  notification channels, and any FCM `google-services.json` live in the host.

### Architecture

Two ports sit at the center, each with a working default and pluggable backends. `ArxaKitNotificationsService` (plural) is the device-notifications port — `initialize`, `requestPermission`, `permissionStatus`, `tokenStream`, `currentToken`, `foregroundMessages`, `showLocalNotification`, `cancel`/`cancelAll`, `setBadgeCount`/`clearBadge`, `dispose` — backed by `LocalArxaKitNotificationsService`, a native-first adapter over `flutter_local_notifications` (UNUserNotificationCenter on iOS/macOS, NotificationManager on Android). `ArxaKitOutboundMessageSink` is a separate port for one-to-one SMS/email, backed by `ArxaKitSmsBackend` / `ArxaKitEmailBackend` stubs. `ArxaKitFcmPushBackend` carries the real `firebase_messaging` signatures but pulls no `firebase_*` dependency; the local default emits nothing on `tokenStream` / `foregroundMessages`, leaving push to the host's APNs/FCM backend. Dependency direction is strictly outbound: this package depends on neither `arxa_kit` core, `stacked`, nor `stacked_services`, and does not import core's singular `ArxaKitNotificationService` (in-app toast/snackbar), which stays in core.

### Decisions / ADRs

**Standalone, not stacked-coupled.** The package deliberately depends on no `arxa_kit` core, `stacked`, or `stacked_services`, so it can be adopted host-side without dragging the framework graph in. **Native-first local default.** `flutter_local_notifications` was chosen as the backing SDK because it maps directly onto the platform notification centers (iOS/macOS UNUserNotificationCenter, Android NotificationManager) and gives real permission + show/cancel behavior out of the box; push (`ArxaKitFcmPushBackend`) is a real-signature stub with no `firebase_*` dependency pulled, so the FCM/APNs seam is owned by the host backend. **Badge is per-notification, not standalone.** Because `flutter_local_notifications` v21 only sets the iOS badge as a side effect of a delivered notification (`DarwinNotificationDetails.badgeNumber`) and Android badges are launcher-specific, `LocalArxaKitNotificationsService.setBadgeCount` / `clearBadge` throw `UnsupportedError` — callers set `ArxaKitLocalNotification.badgeCount` on a shown notification or own the badge from the push payload (a backend may override). **Outbound is a stub seam.** `ArxaKitSmsBackend` / `ArxaKitEmailBackend` are provider-side (Twilio/SendGrid over HTTPS) or native-send seams, wired only when a host opts in.
